# C 语言内存与并发 AI 扫描工具：设计文档包

> 版本：v0.1 · 日期：2026-10-12 · 状态：概念设计，尚未实现或实测
>
> 来源：本次对话中的从零设计方案。本包不以 Z-Scope 的既有实现为前提，也不新增行业调研结论。

## 1. 设计结论

以**内存对象及其生命周期**为主线，以静态分析提供系统性覆盖，以 AI 补齐项目语义并主动探索缺陷，以**可核查、可映射回原程序的错误见证**控制误报。

目标优先级严格为：**低误报 → 高召回 → 扫描性能**。

这不是逐函数调用 LLM 的代码审查器，也不是仅由 LLM 过滤传统工具告警的包装层。其关键区别是：候选发现可以激进，正式报告必须有证据；无法确认的问题保留为未知，不能被当成安全。

## 3. 五条不可混淆的边界

1. **候选不是缺陷。** 已确认、条件性、待验证、已排除必须分开记录。
2. **排除路径不是证明程序安全。** 未复现、超时、有界范围内无错误，均不能直接变成安全结论。
3. **AI 推测不是项目契约。** 契约来源及适用条件必须可追溯。
4. **互斥不是生命周期保证。** 同一把锁下串行执行的操作仍可能产生 UAF。
5. **低误报不能靠隐藏未决问题达成。** 正式召回、未决候选、解析失败与预算不足必须同时披露。

## 4. 统一术语

| 术语 | 含义 |
| --- | --- |
| 对象 | 实际或抽象的内存对象，关联存储区域、实例区分和生命周期代际 |
| 事件 | 分配、释放、访问、逃逸、同步、回调注册等具有程序语义的操作 |
| 摘要 | 带前置条件、路径条件和副作用的可组合函数行为描述 |
| 契约 | 标准接口或项目接口的语义说明，须区分已接受事实与待验证假设 |
| 候选 | 尚需满足证据要求的缺陷假设 |
| 错误见证 | 在声明的构建、契约和环境内，能够具体化为原程序合法输入或执行顺序的错误路径 |
| 正式缺陷 | 已满足对应缺陷类型证据要求、进入正式报告的已确认问题 |

## 5. 文档使用约定

所有能力均为**规划能力**，不是现有产品能力声明。文中的 98% 精确率是拟定目标，不是实测结果或保证；技术组件是候选后端，不代表已经验证集成可行性。

本包不承诺百万行 C 程序“零漏报”，也不把工具未支持的构建配置、语言扩展或同步原语默认视作已覆盖。新增限制必须在报告中显式呈现。
