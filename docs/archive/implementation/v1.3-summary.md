# Z-Scope V1.3 更新说明

> **历史文档，2026-11-17 整理归档。** 原位置：`new_docs/stage1optimation/Z-Scope-V1.3更新说明.md`。正文中的状态、接口、路径、测试与后续建议保留记录时含义；当前说明见[文档总导航](../../README.md)，本类记录见[归档索引](README.md)。

> 本说明汇总 `stage1optimation` 目录下三份实施记录，描述已记录的实现结果与验证边界。它不是新的实施计划，也不把原记录中的“下一步计划”视为已交付功能。

## 版本概览

- **实施范围**：Agent/上下文优化、工具契约与运行时重构、全局建模和后端物化一致性。
- **记录时间**：2026-07-03 至 2026-08-05（不同子模块的最后记录日期不同）。
- **主要目标**：减少重复上下文和无效 LLM 交互，统一函数/类型身份与快照结构，提升跨入口建模、增量缓存和 SVF 数据恢复的确定性。
- **适用对象**：以 C/C++ 分析链路为主；记录未证明 Java 或完整端到端 benchmark 的性能变化。

## 主要更新

### 1. Agent 与上下文契约

- 合并 `semantic_modeler` 的固定 skill 内容，并卸载 `validator_agent` 的固定 skill 绑定；保留原 skill 文件作为参考，运行时减少重复 prompt。
- Semantic Modeler 输出 schema 与 deterministic snapshot 对齐：
  - 使用统一的 `index_name/file_path/start_line/end_line/signature/snapshot_kind` 身份字段；
  - `inputs/outputs` 收敛为 `parameters/return_values`；
  - `memory/resources/concurrency` 收敛到结构化 `effects`；
  - `error_paths` 收敛到 `error_handling.error_paths`；
  - 增加轻量级 `callers`，并将 `suspicious_points.category` 收紧为审计大类枚举；
  - 删除 deterministic snapshot 的 `confidence` 和旧的 `key_semantics` 顶层字段。
- 建立程序字段与模型字段的所有权边界。函数身份、调用边、全局/宏/类型引用、截断元数据和 callee 结构由程序生成或透传；模型只负责当前函数的语义字段。模型伪造或缺失程序字段时，最终快照仍以程序输入为准。
- 统一四条 Semantic Modeler 建模入口（global、entry、premodel、on-demand）的输入构造，使用 canonical `index_name`，校验 Function Info 与实现代码的身份一致性，并在调用 LLM 前报告稳定失败原因。
- 快照上下文逐步纳入 `referenced_globals`、`referenced_macros`、`project_callees`、`external_callees`、`unresolved_callees` 和 `referenced_types`。对应的 symbol/dependency/type fingerprint 用于判断是否需要刷新。
- project callee 与 external/unresolved callee 分流；callee summary 只从 canonical callee snapshot 逐字透传。summary 变化执行 program-only reconciliation，不重新调用 LLM；结构、代码或类型上下文变化仍要求重新建模。
- 新增类型上下文提取与刷新链路：KnowledgeDB 保存直接类型引用，保守解析 resolved/unresolved 类型，限制单项/总定义预算，并在 definition、引用类别或截断状态变化时触发 `type_context_changed`。
- Semantic Modeler 改为单会话 `emit_function_snapshot` terminal tool：检索工具和最终提交在同一会话完成，独立统计 terminal 调用与普通工具调用。无效 terminal payload 在当前会话回灌错误；重复无效提交达到阈值时触发 terminal loop guard，并使用全新 Agent 会话最多重试两次。
- 修复头文件入口到源文件实现的解析：仅在 header-like 路径严格查询无结果时去除文件约束，并要求索引唯一选定实现，避免同名函数被任意绑定。
- 全局模型阶段门禁调整为：入口未解析或 reconciliation 失败仍零容忍；少量非入口 callee 建模失败（`failed_functions <= 10`）可继续入口 fan-out，但跳过阶段末 reconciliation，不伪造缺失 summary。

### 2. 工具与运行时

- 将原集中在 `zscope/tools/utils.py` 的十个工具拆分为独立模块，保留兼容 re-export；新增统一 `build_tool_registry()`，稳定控制 13 个内置工具的名称和顺序。
- 统一工具参数校验：`BaseTool`、Agent executor、`ToolsRuntime` 和 strict policy 共享同一套 required/type/enum 校验；Runtime 删除逐工具硬编码 schema、分支 dispatch 和重复执行实现。
- `get_function_info` 完成从索引、KnowledgeDB、Clang/Unified backend 到 Agent 的完整链路：支持 canonical 函数键、宏函数、调用边、全局/宏/类型引用及独立 truncation 元数据。
- CodeIndex 函数身份统一为 `func_name@file_path:start_line-end_line`，同时保留简单名、限定名和签名 alias；`get_function_impl` 支持 name/signature/index_name，并在精确查询失败后执行受控 fallback 和 canonical cache 复用。
- `get_callers` 改为 canonical 输入和结构化输出：只接收 `func_name` 与可选 `file_path`，固定最多 20 个 caller，按 caller identity 聚合调用行和 direct/indirect 类型；支持 function-like macro fallback。
- `get_type_info` 支持可选 `file_path` 和多候选返回 `match_count/matches`；公开结果以 source-backed `full_definition` 为类型主体，不再返回 `members/id/tu_id`。Runtime negative cache 按 `type_name + file_path` 隔离。
- `get_function_snapshot` 在无 on-demand resolver 时提供 canonical Function Info fallback：缺失或过期 snapshot 返回 `data=null` 与 `snapshot_status/reason/function_info`，不会把 stale snapshot 交给 Agent。
- `get_function_info` 与 `get_type_info` 的严格 `file_path` 查询零命中时各自执行一次无路径 fallback，返回全部候选并附带 `file_path_fallback` 诊断；不会自动选择第一项，也不会污染 type negative cache。
- 工具层补充普通函数 `is_static`、宏查询、宏/全局引用规范化和 `/tmp` 项目宏扫描修复；LLVM intrinsic 在 CodeIndex 输出边界过滤，不占用 callee limit，但底层 KnowledgeDB 的原始 indirect fact 仍保留。

### 3. 架构、缓存与后端事实

- 增加 `analysis.enable_global_model` 配置开关（默认关闭）。开启时，GlobalModeler 在 entry worker fan-out 前构建跨入口可达图，使用支持 SCC 的 ready-queue 调度，并复用已有 deterministic/LLM snapshot。
- SnapshotStore、lock、cache、SQLite 主键、文件名和调用方统一迁移到 canonical `index_name`；旧复合主键数据库提供事务迁移，旧 deterministic shape 会以 `snapshot_shape_changed` 触发重建。
- deterministic snapshot 建立 canonical 顶层字段顺序和严格 shape 检查；`trivial`/`lightweight`/`LLM-modeled` 的程序字段、callee 分流、symbol/type context 和 evidence projection 统一。
- 快照刷新 fingerprint 分为代码、语义、symbol/dependency、callee summary 和 type context 等维度。callee summary 变化可执行原子 program-only 更新，避免无意义的 LLM 重建；跨上下文变化不会复用旧 final report。
- SVF/KnowledgeDB 物化一致性永久修复：引入数据库 generation、每个 Ander/Saber group 的 artifact marker、全局 materialization manifest、artifact hash 校验、replay 文件和 savepoint 事务。有效 artifact 在派生表被 purge 后可直接重导入，不必重复运行 WPA；失败时保留旧 group 数据和 marker。
- Clang/KnowledgeDB 增加 `callee_kind`、SVF callsite-aware 字段和 `callee_signature` 链路。只公开具有充分源码证据的函数指针调用点；无法证明映射时保持 opaque/unresolved，不把占位符伪装成 external 函数。
- project callee 宏去重完成：可唯一解析的 function-like macro 归入 `referenced_macros`，不再作为 project/external callee 持久化；KnowledgeDB schema 与 extractor version 提供迁移和自动重建。

## 契约与迁移影响

- **快照调用方**：应使用 `index_name` 作为持久化、锁和缓存身份；顶层 `location` 仅保留在 suspicious point、issue 或 validation evidence 等源码证据中，不再作为 snapshot identity。
- **Semantic Modeler**：LLM terminal/structured schema 不再暴露程序拥有字段；调用方必须提供 required program context。输入非法时返回 `semantic_model_input_invalid` 且 `llm_called=false`。
- **函数/类型工具**：调用方需要处理多候选、`file_path_fallback`、`data=null + function_info`、`snapshot_status=missing/stale` 等显式状态，不能默认读取 `matches[0]` 或把 stale data 当作有效证据。
- **KnowledgeDB**：记录中已实现从 schema 8 至 13 的增量迁移，涵盖 symbol refs、type refs、canonical macro、`callee_kind`、callsite-aware indirect calls 和 callee signature。迁移失败应保留旧数据，不提交半成品。
- **兼容性**：`zscope.tools.utils` 继续 re-export 已拆分工具；部分旧内部 API 保留用于迁移或兼容，但公开新契约以本说明所列结构为准。

## 已知限制与未宣称事项

- 系统头、平台 SDK 和部分外部类型可能以 unresolved 形式进入上下文；Joern-only、regex type fallback、无 KnowledgeDB 宏能力的 backend 覆盖低于 Clang 主路径。
- 外部函数签名依赖 backend 明确提供的 `callee_signature`；runtime snapshot allowlist 和 `external_function.config` 集成未在这些记录中完成。
- backend 未提供的调用边不会被 summary reconciliation 猜测恢复；无法将 SVF source port 与源码调用点唯一映射时，只保留底层事实或 unresolved 记录。
- SnapshotStore 的 JSON 文件与 SQLite 提交仍存在跨介质失败时留下孤立新文件的风险，后续可增加补偿式提交流程。
