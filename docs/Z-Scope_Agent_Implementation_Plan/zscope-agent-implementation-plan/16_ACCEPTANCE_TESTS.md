# 16 · 验收场景与正反例

本页是新增能力的测试规格，不是已通过成绩。优先扩展 [02](02_ARCHITECTURE_AND_REUSE_MAP.md) 的已有测试，不按场景编号机械建立重复测试。所有质量命令在 Linux/WSL 执行，fake、真实工具、真实模型结果分别报告。

资源接口专项新增验收 `RAPI01–RAPI10` 的场景、任务 ID 和可观察结果统一见 [22 第 5 节](22_RESOURCE_API_INFERENCE.md#5-验收编号与可观察结果)：首批覆盖发现出处、载体/分支、副作用、消费者一致性和失效；后续覆盖跨 TU/函数指针、refcount/池/句柄、锁/RAII、异步与完整增量。它们复用下列 RES/VAL/CON/INC 场景；RAPI01–RAPI05、RAPI06 受限链接/const ops，以及 RAPI07 的非原子计数/池状态和有界自定义句柄表的实际 Linux/native 回归、pass/fail/skip 及限制见 [21](21_IMPLEMENTATION_STATUS.md)。RAPI08 的锁模式切片也已记录：读写保护、失败 try、EOWNERDEAD、当前包装器与实例、等待/递归/升级拒绝和签名失效；不等于完整 CON 场景完成。RAPI08 的单指针 scoped heap guard 正常/提前退出、明确捕获 throw、空 guard、custom deleter、身份失效及拒绝边界见 21；RAPI07 平台/通用子域、复杂 RAII/通用锁协议仍待办；RAPI09 单工作者延迟回调与受限单槽队列切片见 21：提交/取消/停止接收、活动任务旧引用、同锁 UAF、成功 join 后释放已有实际 native 验证；单等待者 cond_wait 的通知实例、锁重获、返回值/条件重检、提前通知不留额度及失效对照已接入；一般唤醒/超时场景、取消模式切换/任意取消点、一般工作者 helper 与通用队列/drain 仍待办；RAPI10 当前协议与头文件否定性依赖切片已验收，完整增量/调度仍待办。定向测试不等于正式准确率评测。

## 构建与身份（S01）

| ID | 场景 | 可观察结果 |
|---|---|---|
| ID01 | 同一源码两组宏/ABI 编译 | 两个实例的事实、契约、候选、缓存不串线，未处理变体显示缺口 |
| ID02 | 两个 TU 的 static 同名；不同 executable 的 global 同名 | 精确区分；同目标重复强定义单独诊断，不丢 TU |
| ID03 | 同分配点不同调用实例、地址/句柄释放后复用 | 不以抽象对象/数值相等确认 UAF/double free |
| ID04 | 头文件/响应文件/编译参数/链接目标变更 | 相关证据失效；未变正文不能使旧结果继续有效 |

| ID | 场景 | 可观察结果 |
|---|---|---|

| RES05 | 人工规范、实现、文档互相冲突 | 来源/适用条件并列，自动推测不覆盖人工输入或直接确认 |

| RES08 | 成功留存后归还、失败保留、cancel→complete 的具体调用链 | 同 TU/构建下原生 CFG 和调用帧绑定同一池/对象/获取代次；正常清理、失败后重试留存、不可达 cancel 为反例。业务释放规范和责任终点独立保留，不用入口退出自动确认泄漏 |
| RES09 | 归还后地址复用、错池、同站点重复 call 事件 | 同地址新获取生成不同 ObjectRef；旧代指针触发新代归还与同代重复尝试分开。分析计数器不是业务 generation 永不回绕证明；重复事件不重复执行 API |

| VAL09 | 当前源码重放后只缺业务规范 | 对象/代次/路径和源码契约均匹配时才呈现 business_conditional；业务前提标记 analysis_requirement/unconfirmed，带适用对象、入口和来源，不写成已确认责任 |
| VAL10 | 源码/契约/构建变化、旧报告或伪造收据 | 重新扫描必须重新核验；旧/修改/模型自报字段、缺 provider 或技术缺口保持 protocol_pending；当前核验结果参与 Validator 缓存身份 |
| VAL11 | 模型禁用、模型三态、高分或清空缺口 | 禁用模型仍进行路径核验；模型三态及评分不代替业务授权，删除缺口清单不绕过统一 needs_review；报告和单条 Markdown 保留验收问题及依据 |
| VAL12 | 范围明确的用户声明与完整当前路径 | 必要前提全部 yes 才能沿统一程序 proof 确认；缺责任终点或后续访问不确认；回答来源、范围与版本随报告保存 |
| VAL13 | 业务回答撤销、修订或扫描中发生变化 | 旧程序收据失效，相关业务事实撤回并重验；维护扫描与 resume 不跳过依赖旧版本的报告，受影响历史结论重新进入候选台账；无关回答不导致该结论失效 |

通用 Q01/Q02 后续补用户修改保护、多文件冲突、真实修复前后回归即可；原 SEC 审批/沙箱平台验收不再属于本计划。

RAPI09 延迟取消切片新增实际 native 正反例：取消前/等待中/已通知后投递、先重获 mutex 后 LIFO cleanup、注册值与后续别名重赋值、pop(0)/pop(1)、cleanup 中 UAF/free、无 handler 的 testcancel、持锁 join/失效存储/锁残留、改写宏/未知 helper/取消模式/控制跳出/异常宏变体拒绝，以及集中验收和回答撤回。RAPI10 对照 cleanup 体、直接目标、根契约和 drain 顺序；JSON 不恢复授权，无观察不证明安全。当前仍非动态 pthread 或 Sanitizer 验收。

RAPI09 工作者 helper 切片以真实 native 提取核对嵌套调用、unlock/cond_wait 暂停后发布返回值、重复调用的帧隔离、原对象别名、实际 free、testcancel 与跨层 cleanup 的注册归属。递归、局部地址返回/参数、未知目标及 cleanup 内 helper 保持 unknown；见证篡改、旧根契约和 JSON 不授权。RAPI10 在两 TU 对照 helper 体、目标、返回、取消点、根契约与 drain 顺序变化，比较完整路径、候选身份、裁决、未决和覆盖；原样热复用与独立冷分析分别记录真实编译数。业务回答撤回须重新打开缺口，实验默认关闭；不以本切片关闭完整 RAPI09/RAPI10。

RAPI09 等待结果切片：无通知唤醒不自动满足谓词；while 必须重检并可能再次等待，timedwait 的 0/ETIMEDOUT 分支按实际 CFG 区分，返回前必须重获原 mutex，取消先清理且不得发布普通返回。当前系统 timespec/常量、截止时间范围与时钟前提需有收据；错误纳秒、负秒、未知值、显式转换、项目/包装宏、缺收据及未支持的 clockwait 时钟拒绝。正反例含旧代对象访问、join 后释放、helper/cleanup 路径、锁阻塞/存储失效、S04 回答撤回及默认关闭。RAPI10 增加截止时间、返回码谓词、宏出处和根契约变化的当前性及两 TU 冷/热对照，检查选中调度与全部尝试范围、候选身份/终态/未决/覆盖；不是全调度或正式准确率验收。

等待截止时间还须核验当前 timespec 的大小、对齐及字段偏移；`-fpack-struct=1` 等布局变化、v1/v2 旧收据或伪造布局均不能授权 timedwait。v3 收据来自真实重建工具；合成篡改仅验证隔离，布局反例必须真实提取。

直接 clockwait 切片复用标准 API v7、timespec ABI、重获锁/取消清理及 S04 重放链；`pthread-wait.v3`/`pthread-deadline.v3` 核验直接系统 CLOCK_REALTIME/CLOCK_MONOTONIC 展开、当前值及调用参数。正反例覆盖两个时钟、超时/0 返回、通知/取消/helper/join、常量重定义/包装/变量/转换、旧或缺收据、ABI 布局和业务回答撤回。0 返回不证明早于截止。RAPI10 核对时钟选择/定义、谓词、根契约和 drain 的旧收据撤回及两 TU 冷热一致；实际结果见 21。一般时间来源、自定义时钟、多次唤醒与完整调度继续待办。

RAPI09 调用方等待切片验收：真实 native 条件变量与 mutex 身份、释放/匹配通知/原锁重获、嵌套 drain helper、重复通知下 while 重检与 if 误退、提前清零标志后 UAF、free 后等待、join 修复和取消 cleanup 范围。相同条件变量的不同锁绑定、无通知/提前通知、无持锁、调用方超时及超限保持缺口；等待返回不自动授权同步存储销毁。路径保留入口到 helper 及实际工作者/cleanup 边，S04 重新核验、业务回答撤回和 JSON 不授权；实验默认关闭。RAPI10 对照 helper 谓词、通知删除、回调目标、根契约与释放次序，核对实际冷热 TU 数、完整路径/候选/裁决/未决/覆盖。只覆盖至多四次调用方匹配通知等待，当前静态切片不代替真实线程执行、Sanitizer 或完整调度验收。
