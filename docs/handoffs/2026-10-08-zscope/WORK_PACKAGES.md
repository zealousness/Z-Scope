依赖：无  
代码地图：CM01, CM02, CM03  
验收项：AC01, AC16, AC17

**目标**：消除分支漂移、已有实现和环境假设；不要求先完成全仓重型扫描。

建立轻量测试基线：对当前工具、配置、candidate-ledger、active-discovery 相关测试先 collect，再在现有批准环境运行不需要网络和重型后端的部分。真实 benchmark 与付费模型测试分开记录，缺环境不阻塞 B00。

**禁止**：自动 pull、切换分支、回滚到交接 SHA、清理用户工作区；把提交信息里的测试计数当作本轮结果。

## T01 — 全文／文件搜索接入现有六工具

批次 `M1` · 优先级 `P0` · 类型 `delivery`  
依赖：B00  
代码地图：CM02  
验收项：AC02, AC03, AC07, AC17, AC18

**目标**：让 Agent 能定位错误字符串、配置键、测试断言和构建线索，不依赖这些内容被索引为符号。

**设计**：扩展 `search_code`，可选 `scope=symbols|text|files`，省略为 symbols；原有 symbols 的四种 match_mode 保持。text/files 首版仅字面量子串，显式传不支持模式应返回准确参数错误，不默默改变含义。复用 `path_prefix/limit/offset` 及有界 envelope，必要时兼容增加 corpus／revision 元数据。

**实现顺序**：
1. 先提供不依赖 SymbolCatalog/clangd/LLM 的检索内核；复用已有安全路径与读取边界。
2. 只遍历获准文本，默认不跟随目录 symlink；拒绝越界文件链接，读取时再次验证路径／文件身份，防止检查后替换。处理二进制、无权限文件、非法编码、CRLF、Unicode 和超长单行。
3. 以固定视图和稳定路径／行顺序分页；不要求为了 total_count 扫完整仓。受扫描预算截断时返回 partial、已扫范围和恢复提示，不能仅返回空列表。
4. search 命中用现有 `read_code(file_path,start_line,end_line)` 续读，不创建新文件读取工具。两者采用同一目标根与语料许可。
5. 同步 ToolContract、Agent/MCP schema、角色策略、schema fallback 和工具选择 fixture。

**输出**：实现、正反例、工具用例与文档。文件检索不要求先建 AST，不新增必需的 rg／向量库；可选加速器后续基于测量加入。

**关键用例**：搜索定义体中的日志而不是符号名；字符串只出现在配置或测试文件；路径含空格／中文；分页前后代码变动；目录或文件链接跳出 root；敏感／truth／报告文件不返回；没有命中与没有权限覆盖可区分。

**完成条件**：旧 symbols 契约回归通过；搜索－读取两步能定位片段；部分扫描不会声明 complete；candidate-blind profile 的检索不能绕过结论语料隔离。

## T02 — 严格只读的语义上下文查询

批次 `M1` · 优先级 `P0` · 类型 `delivery`  
依赖：B00  
代码地图：CM02, CM04  
验收项：AC02, AC04, AC07, AC18

**目标**：为 MCP 与发现 Worker 提供不会隐式建模、持久化或启动后端的语义查询。

**设计**：可选 `refresh_policy=cache_only|ensure_current`，正常旧调用默认等价 ensure_current；只读 profile 在服务端强制 cache_only。仅 function 请求有刷新含义，其他 kind 的组合按清晰契约校验。最终字段名可根据既有 API 调整，但要记录决策。

**注意代码陷阱**：当前有 resolver 时直接进入 resolver；无 resolver 路径仍调用 `build_semantic_model_input`。不能仅令 resolver=None 就宣称严格只读，需审计 helper 是否会构建索引、补齐类型引用或写入状态。freshness 只能使用已有可验证元数据，无法确认时返回 stale／unavailable 与原因。

**实现**：把副作用执行与缓存读分开；缓存缺失、过期、损坏、输入版本未知都必须可观察。candidate-blind 输出只包含允许的程序事实／已授权契约，排除 suspicious_points、旧候选、review hint 和结论性 metadata。类型化字段投影优先于对字符串泛化删词。

**完成条件**：通过 spy／monkeypatch 证明 resolver、LLM transport、语义写入和后端启动调用次数为 0；比较请求前后的语义持久状态。正常审计日志可写，但不得把“只读”扩大成“没有任何日志”。对代码／头文件／契约 revision 变化保守处理，不返回伪 current。

**兼容边界**：混合模式 MCP annotation 继续保守 non-readonly；只读服务 profile 仅在所有调用强制只读时标 readonly。新参数支持需涵盖 nullable-required strict schema 与本地递归校验。

## T03 — 只读 MCP 消费方案及 Codex 接入 smoke

批次 `M1` · 优先级 `P0` · 类型 `delivery`  
依赖：T01, T02  
代码地图：CM02, CM07  
验收项：AC05, AC07, AC18

**目标**：本地 Coding Agent 能安全使用 Z-Scope 的事实工具；不新建 MCP Server，不自动修改用户 Codex 配置。

**实现**：核对 `zscope/mcp/` provider、控制面、配置及 tools/list 的真实名称。提供只读、锁定目标项目的 profile／工厂：禁用 scan.run、写操作、任意 cwd/env/output path 和隐式语义刷新。调查子角色额外禁用 static findings／报告／结论资源。普通人工复核角色可另有获准报告访问，不能混为一套权限。

stdio 默认本机使用，协议 stdout 不得出现 banner／进度／日志；日志走 stderr。复用现有远程 HTTP 安全要求，不扩大公网绑定。

文档生成项目级 Codex MCP 配置片段，但不自动写 `~/.codex/config.toml`，不带 token；先使用真实 `--help` 与 tools/list 校验命令、参数和名称。Windows 原生客户端连接 WSL server 需要实际核对 host、路径和环境转发，不假设两个 home 或配置目录相同。

**测试**：协议级自动 smoke 用 fake／临时项目完成初始化、工具列表、搜索－读取、cache_only、越权失败。真实 Codex UI/CLI 联调在具备本地客户端时执行，缺客户端可标 not_run，不影响协议测试结果。

**交付**：可复制的无密钥配置示例、权限表、自动 smoke 与人工联调记录。只读语义标签必须和执行一致，MCP 接入不能触发递归全仓扫描。

## D01 — 动态取证的程序登记与版本绑定

批次 `M2` · 优先级 `P1` · 类型 `delivery`  
依赖：T01, T02  
代码地图：CM02, CM03, CM06  
验收项：AC06, AC07, AC10, AC18

**目标**：为主动调查新增证据，先解决身份与范围，不先放开 Agent 多轮调用。

**起点**：当前 `_validate_report` 只允许原投影 evidence_ref 与单元成员。新结果要进入程序登记表，绑定 code revision、build context、工具版本／参数、目标符号或范围、coverage、原始 artifact 引用；尽量复用现有不可变证据与快照设施，不再造证书系统。

**设计**：新增内部 InvestigationRequest／Result 或等价对象，样例见 examples/，均为提议。模型提交 source refs／查询意图，程序才产生有效引用。查询返回 may-flow 仍是 may，不因登记而变 proof。跨原单元的查询先验证 project、revision、policy 和扩展上限，再登记子范围；没有授权则给出可解释的范围错误。

证据目录可扩展，但原 AuditUnit／Ledger 的身份不能原地变化；通过受控调查清单记录新增范围并参与派生结果 cache identity。缓存需绑定 prompt／model／tool-policy 及所依赖事实；旧结果不因 JSON 中有正确 hash 就恢复运行时证明权限。

**测试**：伪造 ref、旧 revision、同名不同 TU、未登记 artifact、跨项目路径、恶意嵌套 metadata、源码查询后变化、partial/may 误提升。正确两次取证可新增引用并通过原报告映射。

**完成条件**：可用完全 fake 工具演示“初始证据不足→程序授权读取→新增证据→有效 hypothesis”，且任何返回文本都不能自签 proof。

## D02 — 可升级的有界主动调查 Worker

批次 `M2` · 优先级 `P1` · 类型 `delivery`  
依赖：D01  
代码地图：CM03, CM02, CM06  
验收项：AC07, AC08, AC10, AC16, AC18

**目标**：保留一次式发现；仅对关键缺失事实任务升级，不把全仓扫描全部改成多轮重型 Agent。

**实现**：复用现有 JsonToolAgent、工具运行时和 subagent／取消机制。任务从 immutable candidate-blind projection 开始，先给出具体可证伪命题或信息请求，再调用获准工具。可用 search/read/filtered semantic/graph/flow；禁止 static findings、报告与扫描启动，禁止 shell/network。

首轮实验建议最多 4 次取证轮次，可用 2/4/6 做离线消融；这是内部实验默认，不是新用户 YAML、不改变既有模型 completion 上限。用现有局部 RuntimeSpec／scheduler 管理调用、deadline 和取消，不把只计量的 ScanTokenUsageLedger 改成拒绝请求的限额器。

程序依据证据缺口、风险与可查询性决定准入；达到轮次／时间边界、重复相同查询且无新增证据、范围无法闭合时停止，保留 hypothesis/unknown/未覆盖状态。失败重试次数计入执行轨迹；不得通过换 task ID 无限重试。

输出映射回既有 DiscoveryReport／CandidateRegistrar，新增来源与一次式发现区分。主 Ledger 冻结前收集；验证期间产生新问题只能走追加通道。默认 off 或现有 shadow 机制；不得直接让 balanced 变为任意长调查。

**验收**：fake 场景验证第二次查询确有必要且能完成；无证据任务会停止；重复查同一文件不无限循环；取消所有者停止后无遗留请求／进程；关闭功能恢复旧行为。真实模型试验另记成本与独占 TP，不以工具调用次数作为收益。

## D03 — 审计单元与覆盖粒度增强

批次 `M2` · 优先级 `P1` · 类型 `delivery`  
依赖：D01, D02  
代码地图：CM03, CM05  
验收项：AC09, AC10, AC16, AC17

**目标**：减少重复分析与“同文件已有候选所以其他对象被当作覆盖”的错误。

复用 Security Semantic Map／AuditUnit，增加对象／操作位点与构建上下文的覆盖键。区分输入路径、资源生命周期、共享状态／回调、协议契约单元；首次可只实现资源生命周期与回调两类，不虚报其余已支持。

入口根与审计单元分离：多个入口可共享对象义务，单入口也可能有多个单元。保留 occurrence 与入口路径；跨入口共用任务不代表删除入口覆盖信息。未解析回调、未知别名、被裁剪 callee、预算 deferred 均显式留账。

**测试**：同文件两个不同资源对象，仅一个产生候选时另一仍可进入发现；两个入口共享对象只执行一次等价调查但保留两个 occurrence；无直接 caller 的注册回调仍有可达线索；变体不同不合并；改变原始入口顺序不改变稳定选择。

**验收**：单元覆盖计数可复算；风险排序只影响调度，不进入候选盲 prompt；存在一个候选不等于该家族／文件全部检查完。新粒度导致额外成本要独立报告。

## P01 — 构建变体清单与增量－全量差分

批次 `M3` · 优先级 `P1` · 类型 `delivery`  
依赖：B00  
代码地图：CM05, CM08  
验收项：AC12, AC16, AC17, AC18

**目标**：界定实际编译覆盖，并用可信重建检查增量正确性。

第一部分只报告所有编译命令、选中／等价／未覆盖上下文与链接组，不立即展开全部变体。不能仅因字符串归一化相同就忽略影响宏／include／ABI 的差异。公共文件投影和 TU 原始事实分开验收。

第二部分建立小型确定性 fixture 的 mutation replay：函数体改动、共享头文件、宏、compile command、文件删除／重命名、回调目标、negative include 从不存在变为存在。每步将同一最终输入分别增量更新和干净重建，再比较规范化事实及覆盖状态。

允许剔除时间戳、run_id、缓存命中等非语义字段；禁止忽略丢失符号、调用边、资源事件、宏／类型、删除传播或 build context。页面读完不等于全程序完整。首次关注完全支持 fixture 中的零语义差异，随后接授权实际工程；不对任意 C/C++ 特性宣称全局等价。

记录各阶段 wall time、CPU、peak RSS、TU 计划／实际重建／失败／复用。冷／热缓存条件、工具版本和硬件一致；LLM 保持禁用或重放固定输出，避免随机性掩盖增量错误。发现等价性缺陷先修复再报告性能。

**限制**：不默认把超预算局部 SVF 扩大为全仓；不修改现有明确配置语义。预算耗尽保留未覆盖及原因，后续调度不冒充成功全覆盖。

## V01 — ASAN 可执行验证最小闭环

批次 `M3` · 优先级 `P1` · 类型 `delivery`  
依赖：D01  
代码地图：CM06, CM09  
验收项：AC06, AC10, AC11, AC17, AC18

**目标**：把一个内存缺陷候选转为可独立复跑的 witness，而非只增加模型复核。

先设计 provider 协议与 fake runner，再实现一个 ASAN runner。新建单独的正例／反例 fixture，不修改 test/range 中的植入缺陷。真实执行限定获准本地 fixture；未知项目脚本、任意模型命令不得自动执行。

验证计划绑定源版本、候选对象、构建配置、工具链、输入／harness 和允许执行范围。执行器用 argv 参数、固定工作目录、环境变量 allowlist、临时可写目录、超时、资源限制及进程组取消；是否具备真正 sandbox 需如实记录，subprocess 不等于安全沙箱。没有获准隔离环境时只运行 fake tests。

结果保存命令身份、构建／二进制摘要、输入、stdout/stderr、退出码、sanitizer 分类、调用栈、source mapping、重放次数及限制。支持 `witness_observed / not_reproduced / inconclusive / engine_failed / unsupported` 等 provider 层结果（最终名称按现有模型映射），不新增或偷换产品 disposition。

ASAN 告警必须匹配候选对象／站点／缺陷族；同进程发生另一个 crash 不是原候选已证实。Agent 生成结果由独立 runner 重跑；修复版验证可作为回归证据，不能据此宣称全程序安全。

**验收**：真实正例能产生可匹配报告，反例不产生同类 witness；超时／OOM／构建失败不拒绝候选；源码或二进制变化拒绝旧证据；复跑产物完整。无 ASAN 环境则实现测试可过，但 real-execution 项保持 not_run，V01 不应被标完整验证完成。

## K01 — 建模怀疑点的条件性 shadow 回收

批次 `M4` · 优先级 `P2` · 类型 `experiment`  
依赖：D01, D03  
代码地图：CM03, CM04, CM06  
验收项：AC07, AC10, AC13, AC16, AC18

**目标**：恢复建模线索的可调查性，不恢复无证据直报告。

复用 snapshot_candidates.py 的位置解析与既有来源机制，先核对调用方为何暂停。仅接收明确对象或 source/sink、真实代码位置、违反性质、成立条件和 missing facts 的观察；模糊说明保留原背景，不生成独立义务。

将观察进入独立来源的 shadow 队列，不能注入 candidate-blind worker 的初始提示。需要调查时使用明确“建模观察驱动”角色，归因与独立发现分离。重复指向同一义务时由 Registrar 合并，保留来源；不编辑主 Ledger 冻结记录。

**验收**：条件成立／不成立、返回所有权、错误出口、位置无法解析、过期 snapshot、无入口路径分别处理；关闭时与现状一致；统计独占真问题、重复项、待复核积压和额外成本。没有独立收益不得晋升默认 active。

## K02 — 条件接口契约与资格校验

批次 `M4` · 优先级 `P2` · 类型 `experiment`  
依赖：B00, D01  
代码地图：CM04, CM06  
验收项：AC06, AC13, AC17, AC18

**目标**：首先支持“成功转移／失败保留所有权”这一类契约，避免笼统接口摘要误消义务。

沿用现有契约、manual 优先和 user_config 发布机制，扩展条件效果及可消费资格。先确认当前已经表达的字段，不重建工作簿格式。契约提议需绑定接口身份、参数对象、返回条件、资源族／池、构建上下文、来源和版本。

LLM 提议只能影响探索或产生待证事项；解除义务必须经当前支持的实现检查／受限事实提供器资格验证。对未知调用、条件别名、跨分支池身份、失败状态未闭合保持 unknown。

静态 wrapper 合成复用已验证 callee；递归 SCC 保持冻结／迭代上限及发布屏障，不用部分新契约污染同轮其他任务。

**测试**：queue_push 成功／失败、参数换位 wrapper、同名接口、不同资源池、返回码检查遗漏、文档与实现冲突、人工契约与未验证模型提议冲突、修改 callee 导致恰当失效。

**验收**：文档不能单独反驳实现事实；未经验证的所有权转移不会消除候选；静态和 LLM 产物使用同一资格规则。更复杂协议另开增量任务，不借本任务宣称支持任意状态机。

## P02 — 按义务需求进行语义建模试验

批次 `M4` · 优先级 `P2` · 类型 `experiment`  
依赖：P01, D03, K02  
代码地图：CM04, CM05  
验收项：AC09, AC12, AC13, AC14, AC16

**目标**：降低首次全可达并集建模成本，同时不封死尚未产生候选的语义未知区域。

首版只做 shadow planner：原有建模照常执行，记录按需策略会选择／推迟哪些函数及原因。需求来源包含候选缺失事实、敏感但不透明接口、未知回调／别名、文档冲突和覆盖缺口，不能只有候选列表。

保留人工契约与已验证透明 wrapper 的低成本路径。共享相同符号＋输入版本任务、SCC 调度和统一发布；重试所有权不分裂。使用新契约后，重新执行受影响规则与候选收集，不把语义建立后的事实仅交给后续 Validator。

shadow 与原路径比较发现与义务覆盖，再在受限 fixture 中实际跳过。冷／热扫描分开衡量调用数、unique modeling task、重复等待和 token；LLM 随机性通过固定重放／多次真实运行单独控制。

**验收**：构造“没有模型就没有初始规则候选”的接口正例仍会触发建模；变更 callee 影响调用方契约；未计划项和覆盖不明项不缓存为安全。没有足够等价证据，保持 shadow，不修改所有 C/C++ 档位前置建模行为。

## A01 — 外部 Coding Agent 的受限调查适配器

批次 `M4` · 优先级 `P2` · 类型 `optional_integration`  
依赖：T03, D01, D02  
代码地图：CM02, CM03, CM07  
验收项：AC06, AC07, AC08, AC15, AC18

**目标**：需要跨代码／文档／构建材料自主调查时，允许选择外部执行器；普通检索仍直接使用确定性工具。

先实现窄接口、fake adapter 和离线结果导入，再对已获准的一个供应商做 smoke。任务包包含代码版本、审计命题、允许路径／工具、缺失事实、可写范围、网络权限和取消边界；返回结构化证据引用与 artifact，不接受自报 proof。

只读调查默认无 shell、无外网、无 scan.run；实际 SDK 无法强制权限时判 unsupported，不能仅靠 system prompt。生成 harness 属于另一权限 profile，不能悄悄扩大只读任务的能力。工作区使用批准的隔离快照／工作树，不覆盖原源码；credentials 由用户的独立运行环境提供，不复制宿主全部变量或 ~/.codex 内容。

**验收**：fake 验证版本错配、私有路径泄露、shell 越权、递归扫描、取消、错误后复用。真实 SDK 的版本、许可证、接口、认证与数据流在调用前重新核对；未核对不安装。现有 OpenAI-compatible 自托管路径不因外部 adapter 缺失而受影响。

## A02 — Codex Security 独立对照与离线结果接入

依赖：B00, D01  
代码地图：CM06, CM07  
验收项：AC06, AC15, AC16, AC17

**目标**：测量外部安全扫描器是否提供独占价值，不作为原生扫描硬依赖。

先固定实际可用 CLI／SDK 版本与许可、认证模式、访问资格和支持语言／运行环境；外部官方 README 是接口线索，不是用户已有资格证明。1.0 前 API 可变，勿照搬交接时的命令生成永久依赖。
