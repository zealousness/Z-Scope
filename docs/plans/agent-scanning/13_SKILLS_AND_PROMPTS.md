# 13 · Skills、提示词与文档职责

## 四种文档分工

根 AGENTS.md 指导开发者；产品 `zscope/agents/*/AGENT.md` 是运行时契约；`zscope/skills/*/SKILL.md` 是领域证据要求；项目 Wiki/文档/模型是被分析资料。不能为修开发文档重写运行时 prompt。

现有 resource_lifecycle、temporal_memory、ownership_contract、bounds_and_integer、shared_state_race、concurrency_lock_order 等 Skill 应优先扩展。规则目录管理规则 ID/revision/CWE/语言和能力，Skill 不能代替确定性检测器。

## 专业 Agent 的职责

1. 按当前对象、资源协议和未闭合义务调查，使用准确源码/构建身份。
2. 查询只读事实，确需建模时向语义服务提出明确需求；不能把隐式重建当普通读取。
3. 自主提出假设，但所有来源都进入同一候选登记和验证。
4. 关键前提由工具事实、已核验实现或有条件的项目规格支撑；模型置信度不授予证明能力。
5. 共同持锁、未查到调用者、未动态复现都不是通用安全反证。
6. 复现必须忠实真实接口、初始化、所有权和同步；生成物放独立目录。
7. 夜间未知业务问题进入集中队列，继续独立工作；不反复要求用户确认技术步骤。
8. 记录缺口、下一步和原始证据引用；不把摘要或旧结果当当前事实。
9. 不调用网页搜索/抓取/浏览器，也不通过执行命令替代这类功能。
10. 结束时说明确认缺陷、条件/未决、覆盖、实际运行与未验证内容。

这些要求应由代码合同、工具输出和有针对性测试共同落实。提示词负责工作方式，状态正确性和见证核对由程序保证。

## 渐进加载

按任务/缺陷族选择必要 Skill，激活后完整加载有效规范；大参考资料按引用获取。首版静态按工作项选取即可，无需先建设动态插件市场或复杂 load_skill 框架。

工具 schema 单一来源，角色组合围绕调查/建模/复现职责。调整六工具时更新当前调用方即可，不维持无使用价值的旧 alias。

## 新增内容的最小范围

- 生命周期 Skill 增补同代对象、资源域、责任终点、合法转移/保留。
- 并发 Skill 增补 data race 与 UAF 分开、cancel/complete、unregister/drain、引用获取窗口。
- 复现方法可独立小 Skill，调用既有 runner；不复制执行实现。
- 后端诊断按真实失败阶段提供短 playbook；不先做通用系统修复 Agent。
- Q01/Q02 才增加通用 QA prompt，包含补丁前置条件和真实测试。

新增 Skill 的语言归属、证据要求与 builtin_catalog 一起核对；不因为 C++ 支持已有就默认每个 C 协议适用于析构/异常。

## 交接摘要

只保留：目标与版本、构建/对象、有效事实及来源、未证假设、失败原因、执行/产物引用、未闭合义务、待用户业务问题、下一步。摘要不保存隐含推理正文，也不能升级证据强度。

每次行为/证据合同变化同步相关 Prompt/Skill；没有变化不为“整齐”改动全部规范文件。
