当前 Wiki 已有 constraint-only revision 与直接原文 fallback，勿再造自动页面/图知识库。项目 AGENTS 是开发约定，产品 AGENT/Skill 是运行规范，生成报告和 benchmark truth 不进入说明性知识语料。

## 启动项目画像

读取源码布局、构建目标、测试入口、已有文档、工作簿和运行平台，生成简短画像。让用户只确认冲突或未知的关键项：资源归属、长生命周期对象、退出时机、队列失败语义、取消/注销是否等待、硬件上下文。

无需用户列出所有接口或先维护完整 Excel。自动发现并解释“已知/推测/冲突/待补”；对会影响大量候选的公共接口优先调查，夜间无法解决的问题集中到验收。

## 业务模型必须能表达

- 资源族和实例域：同一 pool、allocator、session、设备或事务；错误域归还不是正常释放。
- 载体：返回值、输入参数、输出参数、成员、全局句柄；p、&p、*pp 不能混同。
- 条件：成功/失败返回、部分成功、重试、初始化/关闭阶段。
- 责任：独占、借用、复制、转移、共享引用、保留到进程/模块结束。
- 协议：allocate/use/release、submit/complete/cancel/join、register/unregister/drain、open/close/reuse。
- 并发：谁持锁、何时加引用、是否允许回调在注销后继续、队列是否串行、ISR/DMA 是否并发。
- C++：析构与异常清理、move 后状态、shared_ptr/weak_ptr 和自定义 deleter 的真实边界。

名字只用于查找，不能据此认定 role。当前 ApiContract 已有条件效果等字段；S02 扩展语义与消费者，而不是重新定义简化版 malloc/free 表。

## 来源与发布

来源区分 implementation_checked、user_declared、documented、model_proposed。实现检查可确认其支持的局部效果；人工规格是有适用条件的前提；文档与实现冲突不自动覆盖；模型推测不得签发 must 效果或安全反证。

自动核实的模型可在夜间发布新 revision 并重算受影响项，无需逐条人工批准。必须由业务人员决定的假设保持条件性，验收时批量确认。运行中每个分析批次绑定一致的契约 revision；更新后显式新建批次，不混用版本。

工作簿不再是唯一内部权威载体：目标以结构化模型服务与 UI 表单为主，保留导入/导出实用能力。迁移人工行时保存来源、条件和冲突；自动生成行/缓存可重建，不要求旧存储兼容。

## 经验与反馈

只保存有复用价值的已验证流程、用户纠正和环境条件；完整日志留产物目录。经验至少带项目/平台/构建/模块范围、证据引用、适用条件、active/stale/conflicted 状态。

首版字段匹配+词法检索即可，不引入向量服务前置。中文短词与代码标识符做精确回退。使用前检查来源；“过去没复现”不能变成当前“线程安全”。

验收否定报告时区分：工具确实误报、项目条件未录入、风险接受、重复根因。分别形成规则缺陷、模型补充、显式处置或去重反馈，不能全部写 suppression。

## 衡量价值

看公共模型关闭了多少义务、减少多少 FP、增加多少确认 TP、节省多少重复调查及用户补充次数。知识条目数量、Wiki 字数、记忆命中数均不能单独算收益。
