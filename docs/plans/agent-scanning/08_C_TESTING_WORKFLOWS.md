# 08 · 专业扫描纵向工作流

## A：条件转移、泄漏与重复回收——首条闭环

合成示例：pool_take 通过输出参数取得对象；queue_submit 成功转交队列、失败归调用者；complete/cancel/timeout 竞争回收。

1. 绑定实际构建目标、pool 对象、申请实例与代际。
2. 读取接口实现/调用点/项目约定，复用条件契约编译器。
3. 生成成功/失败/部分成功下的责任摘要和事件。
4. 规则与对象级探索登记泄漏、UAF、double release 假设。
5. 针对同对象、路径、责任终点和等待条件补证，统一验证。
6. 适合运行时生成独立 harness 与输入，复用现有 runner。
7. 交付源码因果链、触发条件、见证和未决项，验收时批量确认未知业务前提。

反例必须覆盖：成功正常转移、失败调用者清理、不同对象实例、错误池与正确池区分、cancel 等待完成、仅借用且始终有效。资源池逻辑归还不一定触发 sanitizer，静态协议见证与状态探针互补。

## B：并发与异步生命周期

围绕同一对象收集线程、任务、回调和销毁事件，分别判断普通 data race 和生命周期错误。共同持锁只排除符合条件的普通竞争，不排除借出指针后分阶段销毁/使用的 UAF。

重点序列：retain 前销毁、submit 后提前释放、cancel 与 complete 双重清理、unregister 后仍在途回调、close 后句柄复用。安全反例包括可靠 join/drain、引用持有、串行队列、CAS 唯一清理和实际上不可并发的路径。

TSan 结果只支持其检测的竞争，ASan 支持其检测的内存错误；两者均不能完整证明协议正确。未知同步原语优先补模型，不能等价为“无同步”。

## C：自动生成与运行复现

当前已有执行/匹配/重放，缺自动生成器。目标链为：

`未闭合义务 → 可复现性判断 → 最小真实链接目标 → harness/输入/故障注入 → 前提与 stub 检查 → 编译/运行/重放 → witness 匹配 → 原统一裁决`。

build profile 保存工具链、目标 ABI、普通/ASan/TSan 参数、依赖、symbolizer 和命令。ASan/TSan 分开构建与日志；固定场景采用真实项目构建系统，不写一个通用 cc 命令假装支持任意工程。

记录测试发现/执行/跳过/失败/超时数，保存每次触发分布。未复现、构建失败、工具不可用、无关 crash 均保持未决；只与当前对象/站点/类别/源码相符的 witness 才可支持确认。主机 stub 改变锁或 ABI 时，只能报告模型范围内的现象。

默认独立目录，业务源码不改。后续修复任务才做 before/after 同目标回归，禁止以删断言、关闭插桩或跳过测试变绿。

## D：后端与编译失败诊断

区分启动/共享库、TU 编译、位码提取、链接、分析和结果消费。记录 cwd、参数、响应文件、宏、目标 triple、LLVM/工具版本和真实链接目标。

同名符号至少分四类：两个 TU 的 static、两个 executable 的 global、互斥宏变体、同一目标重复强定义。先修输入重复、目标分组与身份，不随机重命名业务代码或丢掉冲突 TU。

复验不仅看 exit 0，还看实际输入 TU、入口、调用边、对象事件和 coverage。工具缺失可以继续独立源码调查，但不宣称完整 unified 扫描。

## E：全量、复用与增量对照

代码/头文件/宏/响应文件/构建/契约/文档变化分别传播；加入新访问者、新回调、新释放路径和删除同步步骤的场景。

复用现有 indexing replay 验证事实，再增加候选、最终状态、未决和覆盖对照。同最终代码/构建、独立缓存比较增量与全量；精确 ID 的变化与语义结论变化分开。不要用事实表一致冒充最终扫描一致。

## F：嵌入式/RTOS

Linux 闭环后选择一个真实平台，导入交叉编译、任务/ISR、临界区、静态 pool、设备/DMA 生命周期。主机/模拟器/目标板结果分开展示；未建模硬件行为进入条件和覆盖报告。

首批平台样例优先沿用资源协议 fixture，增加中断打断清理、DMA 未完成归还、任务删除清理和合法关中断/等待完成的反例。

## G：项目资料维护

实际行为、公共字段或所有权变更时同步 README、architecture、对应 modules、配置模板/初始化器和根 AGENTS 导航；规则语义变更同步目录 revision 与 CWE/Skill 契约。

本包是规划，不能把尚未实现的命令写到当前用户指南。规则更新也不应顺带重写全部运行时 AGENT；仅实际证据合同变化时同步相关 Skill。
