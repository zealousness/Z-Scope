```python
    def _emit_sigpipe_unhandled_candidate(
        self,
        view: FunctionView,
        issues: List[Dict[str, Any]],
    ) -> None:
        text = "\n".join(line.text for line in view.lines)
        if "SIGPIPE" in text or "MSG_NOSIGNAL" in text:
            return
        line = self._first_line_matching(view, re.compile(r"\b(?:write|send)\s*\("))

            return
        issues.append(
            self._issue(
                defect_class="sigpipe_unhandled",
                rule="peer_write_without_sigpipe_handling",
                view=view,
                line=line,
                ...
                source=line.text.strip(),
                sink="closed peer write",
                confidence=0.84,             # ← 在这里被硬编码指定为 0.84
                impact_level="high",
                ...
            )
        )
```

### 2. 生成判定逻辑
当 Z-Scope 在 Step 3 进行图/控制流关联分析时：
1. **静态匹配**：`_emit_sigpipe_unhandled_candidate` 方法会检查代码的 Function View，若发现代码中存在向类似 `peer` / `socket` / `fd` / `conn` 等字样的对象进行 `write()` 或 `send()` 的写入操作，且其函数或上下文里**完全没有**看到 `SIGPIPE` 屏蔽或 `MSG_NOSIGNAL` 标志的设置，则认为这极有可能是未捕获的 SIGPIPE 隐患。
2. **规则定级**：因为这一特征匹配的规律性很强，在静态检测的评估设计中，该检测模式被赋予了 **`confidence = 0.84`（84%置信度）** 的先验安全分。
3. **输出转化**：这个置信度值在转化为结构化候选证据（Structured evidence）打包时，成为了 `rule_confidence`，并最终成为了影响工单优先级评分（`priority_score`）的一个加分依据。
