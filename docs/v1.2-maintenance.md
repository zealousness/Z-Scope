# v1.2 维护分支

`v1.2_feat` 从 `2a65c1f6301c` 延续 v1.2 的入口驱动分析、函数身份、Snapshot 和 Validator 协议，包版本仍为 `1.2`。本分支引入可独立复用的后端、缓存和客户端修复。

## 默认生效的修复与优化

- 源码和函数正文缓存绑定文件身份、ctime、mtime、大小及索引代次；替换同大小、同 mtime 的源码也会重新读取。两类缓存共用 512 MiB 的内容字节预算和 LRU 淘汰；该预算不代表 Python 进程总内存上限。
- 带文件提示的函数查找使用名称和签名倒排索引，未命中时不遍历整个函数表。头文件作用域每个文件计算一次，重叠 glob 不重复扫描同一文件。
- clangd 请求使用固定单调时钟超时，持续索引进度不延长请求；服务端请求独立应答。停止、EOF、写入失败会唤醒等待者，晚到响应和旧进程消息不会进入新请求。
- SVF 缓存同时检查输入、输出文件摘要和数据库导入标记。数据库事实被清理后，可从有效 DOT/JSON 产物恢复；产物缺失或损坏时重跑相应分组。导入按分组事务提交，失败时保留此前有效数据，零边结果也可缓存。
- Saber 在已有 SVF worker 数量和堆预算限制下并行处理独立分组；默认一个 worker 时仍串行。分组导入使用数据库事务锁，防止多个导入交错；并行进程仍会增加总内存占用。
- Joern 函数名、类型名、正则和文件过滤值编码为 Scala 字符串字面量。
- 工具循环重新核验重复调用的当前结果，结果变化时重置重复计数；仅禁用持续产生相同结果的工具，其他工具仍可补证。消息投影保留 provider reasoning metadata，完整会话保留供审计。

## 可选的性能开关

多 clangd 分片默认关闭。可在扫描前设置：

```bash
export Z_SCOPE_CLANGD_SHARDS=2
zscope -c /path/to/project/zscope.yaml
```

`1` 使用原来的单进程提取器，最多使用 `4` 个分片。分片按目录分配，过大的目录会继续拆分；每批并行收集基础事实，再由调用线程统一写入 KnowledgeDB。分片增加进程和 preamble 内存，应按实际工程比较吞吐与内存后选择。

按入口范围预规划 bitcode 默认关闭：

```bash
export Z_SCOPE_SVF_LAZY_BITCODE=1
zscope -c /path/to/project/zscope.yaml
```

预规划复用现有 KnowledgeDB 和入口 scope，只编译计划内 TU；之后仍按真实 bitcode 执行原有分组、符号闭包和链接。计划为空、不可用或失败时使用完整编译。它适用于已有可靠索引、且入口影响范围较小的工程，不提供超出原 scope 的全工程完整性保证；首次比较时应核对编译 TU 数、链接结果与分析覆盖。

可用 `unset Z_SCOPE_CLANGD_SHARDS Z_SCOPE_SVF_LAZY_BITCODE` 恢复默认单 clangd 和完整 bitcode 编译。

## 验证入口

所有质量命令在 Linux 或 WSL 虚拟环境中执行。

```bash
python -m pytest -q tests/test_v12_maintenance.py tests/test_svf_cache.py tests/test_svf_saber_parallel.py tests/test_build_llvm_lazy_plan.py tests/test_llm_client_tokens.py
```

`test_v12_maintenance.py` 包含真实两个 clangd 进程的冷提取与热缓存复用检查。未安装 clangd 时该项会明确跳过。SVF 恢复、并行调度和预规划测试使用临时 SQLite、DOT/JSON 产物及可控工具 runner，不替代实际 WPA/Saber 或 LLM 扫描准确率评测。Python 支持声明继续为 3.9 及以上。
