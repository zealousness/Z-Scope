# 07 · 工作区、复现执行与恢复

## 默认扫描不改业务源码

记录本次实际源码状态，包括未提交内容；不能只复制 HEAD 后声称扫描的是用户当前工程。构建、harness、输入、日志放独立 run/variant 目录，ASan、TSan、普通构建、位码产物分别保存。

必要的 host stub、调度控制或测试用编译改写属于复现模型，记录与原程序差异；关键释放、同步、所有权语义不得被桩函数改变后冒充真实缺陷。

不新增沙箱/权限平台；进程组、超时、日志/RSS 限额、版本检查用于运行可靠性和准确结果。现有 runner 按实际执行条件使用，不要求先迁移到容器框架。

## 复用现有执行器

`dynamic_reproduction.py` 已有计划、availability、执行、重放、解析、对象匹配、日志和预算。S05 重点补自动 plan provider、harness/input 生成、build profile 与扫描调度；不要新建平行的 sanitizer 执行器。

现有全局 plan provider 接缝应改为 ScanSession 持有的服务，避免两个项目/作业串用计划。候选绑定、计划、日志、二进制、当前源码分别校验；需要时把通用 process 功能从现有实现提取，共用一处。

## 执行状态

`prepared → running → exited | cancelled | timed_out | lost`。

记录 operation/execution ID、实际 argv/cwd/profile、PID/启动时间、build context、开始结束时间、退出码/信号、stdout/stderr、产物和资源消耗。start 快速返回，poll/wait 有界，日志持续落盘并显示最近活动；无输出不等于卡死。

取消停止新任务，并清理本作业持有的进程组；共享索引/客户端由 session 所有者关闭。不能只杀父进程而遗留编译或测试子进程。

ASan/TSan 的虚拟地址空间与普通程序不同，不用一个过低 RLIMIT_AS 制造运行失败。使用实际可行的 RSS/输出/墙钟控制，记录所施加的限制；环境失败与源码缺陷分别报告。

## 输入、产物与恢复

- 源码、依赖、编译参数、工具链、harness、输入和二进制都参与结果身份。
- 执行前以及 build→run 间核对有关内容；发现漂移则重建或标失效。
- 每次重放保留独立原始日志，不能覆盖前次或仅留一个无法定位的摘要。
- 进程已退出但退出状态未持久化时，核对 owner/结果文件；不能猜测成功。
- 不承诺所有副作用 exactly-once；采用动作去重、前置记录、状态核对和必要的新 attempt。
- 动态确认的进程内 receipt 不由 JSON 恢复，首版重启后重跑必要 witness 校验。
- 自动派生产物可清理，未完成作业引用的证据与用户文件不可误删。

## 后置补丁能力

Q02 的 apply_patch 使用当前文件摘要前置条件，逐文件原子替换、多文件操作日志和冲突处理。用户的新改动优先保留，Undo 同样检查版本。不得 reset/clean/stash 整个用户工作树作为常规步骤。

修复任务必须同时保留修复前证据与修复后实际构建/测试；空测试、全 skipped、旧 XML 或一句 PASS 不算验收。

## 平台

产品质量命令在 Linux/WSL Linux 用户态运行；嵌入式交叉编译、主机复现、模拟器与目标板执行分开记录。目标 ABI、调度和硬件协议不匹配时仅支持条件性结论。

Portable 安装与打包复用仓库现有路线，本章不新设发行门禁；缺少可选后端仅影响依赖它的工作项。
