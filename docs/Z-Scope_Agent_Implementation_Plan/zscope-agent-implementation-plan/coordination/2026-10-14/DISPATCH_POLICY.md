# Z-Scope 项目调度标准

本标准只作用于当前 Z-Scope 项目。来源：用户指令经源会话 `01a1387a-0b36-750e-94ef-b034942e3017` 于 2026-10-15 转达；复杂任务分配于 2026-10-16 再次按用户原话更新：“astra额度消耗较大，之前的策略需要改变下，就算任务特别复杂困难，也先交给6.1-sol”。此更新只同步模型偏好，不解除平台限制，不授权重试被拦操作或恢复服务。

- 普通非 UI 开发及返修优先 ZCode `glm-5.3`；Kimi 暂停新派单，已有成果保持冻结。
- 同一工作项由 GLM 实际开发或返修交付后，连续超过 3 轮仍未达到验收要求，即第 4 轮及以后仍失败，升级至 `gpt-6.1-sol`。平台允许执行的特别复杂困难工作也先选 `gpt-6.1-sol / xhigh`；此前仅因复杂度直接交 Astra 的策略已替换，既有任务及成果不重做、不重复派发。
- 升级后的思考强度使用极高（`xhigh`）。UI、前端和用户体验仍由 Astra 负责；适宜的简单确定性任务仍可由已核实的 DSH 承担。
- 按逻辑工作项跨 task ID 追踪，不因换 ID 重置计数。网络超时、认证或调度失败不计开发失败；协调者无效探针、已核实过期测试断言也不冒记为产品开发失败。
- 只有完整的该工作切片独立验收通过，才结束其连续开发失败记录；父包仍有未覆盖范围不等于已经验收的切片失败。新发现的消费端集成义务单列，保留与原工作项的关系，不能借新 ID 隐藏同一义务的连续失败。
- 当前已独验的三个工作切片保持成果，不重做、不重复派单。各自失败与通过收据保留，不能简单相加为整体验收结果。
- 升级用于质量和复杂度匹配，不用于绕过平台限制。出现平台拦截时停止受影响操作并报告，不通过换路由绕过。
- 派单前核对原 Agent-Bridge owner、当前任务、隔离目录和文件所有权；共享文件由协调者集成。测试保持 WSL/Linux、默认 fd capture、ext4 临时目录和两个共享验证槽。

跨任务开发轮次与独立验收结果记录在 `tasks.json` 的逻辑工作项及 `glm_delivery_rounds` 中。历史 S06-R02 已归档，不恢复或重派。

2026-10-17用户补充：原Bridge公开访问阻塞时，允许通过当前正常公开Bridge新建替代任务继续原逻辑工作项未完成范围，无需等待旧owner恢复。新任务须使用独立目录、关联原task/session与全部收据、跨ID保留真实失败计数及原模型轮次；不重复已验收切片。此授权不适用于平台审核拒绝，不授权协调者启动或重启Bridge、私有RPC或直接worker访问；旧S06-R02约束不变。
