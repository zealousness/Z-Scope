## Current tree

The high-confidence local scanner found no private key block, AWS/GitHub/OpenAI-style credential, or private IPv4 HTTP endpoint in the current tree. Generated reports, local `.env` files, caches, Java `target/` directories and benchmark run directories are ignored. CI additionally runs Gitleaks and dependency review.

## Full Git history remediation

The 2026-08-10 full-ref audit scanned 262 unique Git trees and found one high-entropy OpenAI-style credential value (redacted fingerprint `sha256:3b3f96e686dbe942`) repeated in historical configuration/conversation-export paths across 135 tree revisions. A second `sk-...` value was classified as a low-entropy placeholder and is not treated as a credential.

On 2026-08-10, the credential administrator confirmed that this fingerprint belongs to a revoked SiliconFlow API key. The value is intentionally not reproduced in this document or scanner output.

After all 55 local refs were backed up in a verified, Git-ignored bundle, the local repository was rewritten with `git-filter-repo`. Only credential values matching the confirmed SHA-256 fingerprint were replaced. The post-rewrite scan passed across 263 unique Git trees, and the current tree also passes.

The backup bundle still contains the revoked credential and must remain local, access-controlled and excluded from every Release asset. It may be destroyed after the remote migration and retention window complete.

The remaining release blocker is remote coordination: agree on a maintenance window, force-update the affected remote refs, then require every collaborator and runner cache to re-clone. No fingerprint allowlist is needed for the rewritten history.
