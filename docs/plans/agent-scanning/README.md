# Z-Scope Agent 与专业扫描实施计划

**版本：本地校正版 v2.0 · 2026-10-12 · 状态：已进入实施；实际进度见 [21 实施记录](21_IMPLEMENTATION_STATUS.md)，未完成项仍为设计。**

目标按优先级排序：**低误报 → 高召回 → 扫描性能优秀 → 懂用户项目 → 用户使用体验友好**。专业扫描是开发主线；Agent 服务于扫描准备、项目理解、缺陷探索、证据补全与自动复现，通用 Coding 后置。

## 已确认的产品方向

- 默认非工作时间自主扫描；交互集中在启动准备和结果验收，夜间缺少业务答案时继续独立工作并保留未决项。
- 允许自动生成、编译、运行复现测试，使用独立产物目录；默认不修改用户业务源码。修复建议可随报告提供，应用补丁属于后续明确的修复任务。
- Linux 用户态 C/C++ 与嵌入式/RTOS 都重要，先完成 Linux 纵向闭环，再扩展平台语义。
- 重点检查内存、资源及特殊业务生命周期，包括内存池、引用计数、句柄复用、回调、队列、超时、取消和关闭。
- 不承担旧配置、旧 schema、旧工具接口的兼容负担；有实测价值的实现继续复用，冗余实现可以删除或替换。
- 删除原第 09 章，不建设审批平台、沙箱平台或内网运行专题；运行环境按用户给定的可信前提设计。
- **产品不新增网页搜索、网页抓取、浏览器自动化或任意 URL 读取能力。**本地 WebUI 是产品界面，配置的模型 API 是推理服务，二者不属于网页访问功能。
- 开发保持轻流程：小切片、相关正反例、实际验证、简短记录；不要求代码冻结、多级审批、固定观察期或新签名体系。

## 第一条交付路径

`S00 小范围基线 → S01 构建/对象身份 + U01 启动体验 → S02 条件资源模型 → S03/S04 生命周期与验证 → S05 自动复现 → S08 夜间运行与验收`

首个场景：跨文件申请资源，成功时转交异步队列，失败时仍归调用者，取消与完成路径可能重复归还；同时准备正确转移、等待完成后回收和不同对象实例三个反例。首条闭环允许限定单一 Linux 构建目标，不等待通用 Agent、多平台或全部外部后端。

“运行结束”与“没有漏洞”分开；“假设被发现”与“缺陷已确认”分开。有效静态见证可支持确认，无需强制每个缺陷动态复现；未复现不能排除候选。

2026-10-13 纳入 [资源接口识别优化](22_RESOURCE_API_INFERENCE.md)：复用已交付 S01/S02/S03/S04 切片，首批 `S02-R01–S02-R06` 对应独立评估 P0/P1（单构建、同 TU、直接调用，原估算 10–19 有效人日）；后续分别归入 S02/S03/S06/S07，不重建协议或裁决链。当前 S04、受限 C 堆包装器、S03-R01 的已观察链接/const ops，以及 S02-R07 的非原子计数/池状态和有界自定义句柄表，以及 S06-R01 受限锁模式/当前静态锁覆盖，按 [21](21_IMPLEMENTATION_STATUS.md) 记录实际验收和边界；S02-R08 单指针 scoped heap guard 已接入现有 Validator；S07-R01 当前协议与头文件否定性依赖切片已验收。S06-R02 已交付单工作者 pthread 延迟回调，以及受限单槽队列的提交/取消/停止、已取走任务引用、同锁 UAF 和 join drain 切片；S07-R01 已验收直接回调及队列 helper/释放顺序/根契约变化的失效与冷/热对照。后续已接入单等待者条件等待、匹配通知、重获锁和谓词重检，以及对应失效/冷/热对照；一般唤醒/超时场景、取消模式切换/任意取消点和一般工作者 helper 仍保留缺口。平台/通用子域、复杂 RAII/锁 guard、多工作者队列与通用 drain、完整增量/调度仍待办。实验规则默认开关不变。
