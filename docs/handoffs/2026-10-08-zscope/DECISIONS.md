# 实施决策与非目标

## 已确定的设计决策

| ID | 决策 | 实施含义 |
|---|---|---|
| ADR-01 | 渐进增强，不重写 CLI／调度／后端 | 复用 CodeIndex、ToolContract、CandidateRegistrar、现有 store 与 workflow |
| ADR-02 | 保留六工具词汇 | 先扩展 search_code 的检索域；read_code 路径读取已经存在 |
| ADR-03 | 旧调用行为兼容 | 新参数省略时按旧默认；新返回字段不能破坏旧 client 和 strict-schema 路径 |
| ADR-04 | 新主动调查默认关闭或 shadow | 不擅自更改 fast／balanced rollout 默认和晋级规则 |
| ADR-05 | cache_only 在服务端执行 | 不依赖提示词／MCP annotation 约束实际副作用 |
| ADR-06 | 新证据由程序登记 | 模型只引用现有 ID；跨边界扩展需要程序授权 |
| ADR-07 | 不重定义全产品 verdict | 保留既有模型裁决与 proof 区别；外部 witness 按资格加入 |
| ADR-08 | 主 Ledger freeze 不可变 | 关联问题进入既有独立追加 Ledger |
| ADR-09 | 不把预算塞入 usage 账本 | 当前用量账本仅计量；局部调查准入／停止采用现有调度或 RuntimeSpec |
| ADR-10 | 外部服务为可选依赖 | 缺认证／许可／网络时，原生工具与 fake tests 仍能工作 |
| ADR-11 | Linux／WSL 构成验证环境 | 不用 Windows 原生 Python 结果替代仓库要求的产品测试 |
| ADR-12 | 本包是开发资料 | 不作为被测项目 Wiki 或候选盲扫描语料 |

## 不在本轮实施范围

不全量升级 LLVM／SVF，不替换 Clang AST 主后端，不引入向量库作为必需组件，不全面重写 schema，不降低已有证据校验，不增加一套独立裁决系统，不为每个任务建立新数据库／证书／签名协议，不修复 Range 中故意植入的缺陷，不自动安装 Coding Agent 或自动发布扫描结果。

现有产品已有的哈希、校验、审计、安全边界应保留；本文件不是要求删除它们，而是不把开发交接再扩建成一套治理产品。

## 需要本地事实解决的问题

| 问题 | 默认处理，不阻塞全部工作 | 负责任务 |
|---|---|---|
| 本地 HEAD 已前进或有未提交实现 | 读取 diff，复用等价能力；不回滚到参考 SHA | B00 |
| 工具结果模型是否已支持非符号结果 | 先查调用方与 schema 测试；必要时兼容新增分支 | T01 |
| 只读 freshness 如何不触发构建 | 使用持久身份元数据；无法证明 freshness 就返回未知 | T02 |
| 新 evidence_ref 最适合落哪层 | 先复用现有 store／immutable evidence，不单独发明 proof 权限 | D01 |
| 真实工程主要慢在何处 | 分段测量；未测不得预设 SVF 是最大瓶颈 | B00、P01 |
| 动态验证选择哪个模块 | 先用新建最小正反例 fixture；获得授权后接实际模块 | V01 |
| 本地是否有付费模型／SDK／Cyber 权限 | 能力探测并记录；不自动登录、不拷贝用户凭据 | A01、A02 |
| 是否能承担扩大默认发现范围的费用 | 先 shadow 和测量；默认路径不扩大 | D02、K01 |

## 研究假设，不是交付承诺

按需建模可能减少首次扫描成本，但也可能漏掉“尚未产生候选”的未知协议，因此 P02 必须覆盖未知敏感调用并做消融。

更长调查可能提高召回，也可能放大错误假设与成本；必须测量独占真问题和人工复核负担，而不是仅增加轮数。

增量 SVF 或补丁生成检查器可能有价值，但版本兼容性、正确性和真实工程适用性未在本次交接实测。R01／R02 的成功可以是“证据表明不适用并明确停止”，不要求强行并入生产。
