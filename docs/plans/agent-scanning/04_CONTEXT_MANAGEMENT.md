# 04 · 上下文、检索与失效

## 复用与缺口

search/read 的文件、文本和版本化分页已存在；cache_only 语义已实现；V1/V2 为结构化有限输入，V3 才有工具会话。新增重点是对象/协议相关工作集、调查状态续接与跨阶段共享证据，不能把“上下文管理”再次做成完整代码索引。

## 输入分层

| 层 | 内容 | 处理 |
|---|---|---|
| 规范 | 当前 AGENT、激活 Skill、用户限制 | 保留完整有效要求，不静默摘要 |
| 作业 | 目标、范围、build context、当前义务与未决项 | 从持久状态确定性投影 |
| 项目 | 相关 Wiki 原文/契约/业务模型 | 带来源、条件与冲突，不等同程序证明 |
| 证据 | 对象事件、调用/别名/路径、反证、复现记录 | 当前版本、原文可回读 |
| 历史 | 最近调用与失败原因 | 去重，远端压缩成引用 |
| 大产物 | 完整日志、图、测试输出 | 外置，有界分页 |

首选检索路径：已知文件/符号直接读 → 相关调用、类型、宏 → 对象生命周期及跨线程事件 → 对应项目契约 → 缺少的精化/测试。不能只读当前调用栈而忽略另一线程中的销毁。

## 物理窗口与结果投影

输入额度为 `实际模型窗口 − 输出预留 − 协议/估算余量 − 关键工具观察预留`。完整工具 schema 也计入；provider 缓存命中不减少物理窗口。未知 tokenizer 用保守估计并标注，不能把中文字符数当精确 token。

先外置日志、去重复、移除过期片段，再压缩旧工作历史。结果保留完整行/条目、source ref、coverage、missing、truncation 与续读位置。不能截断 JSON 或丢掉“不完整”字段。

不沿用原方案统一 64K/37K/固定百分比作为产品约束。根据当前模型、任务与事实包测量；现有 Validator 输入限制也允许调整，但应以义务覆盖与错误率验证，不能单看 token 下降。

## 压缩与续接

摘要保存：目标版本、输入身份、确认事实及引用、未证假设、失败尝试、执行 ID、剩余义务、问题队列与下一步。关键身份由程序填充，摘要模型不能把“可能”改成“已证实”。

assistant tool-call 与结果成组保留；未完成调用不能在压缩时丢失。旧摘要用于导航，关键结论回源。保存 ContextManifest 的来源/范围/版本/省略原因即可，不增加一套全量 prompt 审计框架。

## 失效规则

| 变化 | 需要重新检查 |
|---|---|
| 源码/头文件/宏/响应文件 | 相关编译实例、对象事件、摘要、证据 |
| ABI/编译参数/链接目标 | 对应 build context 全部派生事实和测试 |
| 契约/业务模型/文档 | 依赖该条件的候选、排除理由与摘要 |
| 新增访问者/回调/销毁入口 | 原有共享集合、单线程假设、否定性结论 |
| 删除文件/实现/同步步骤 | 旧引用与依赖闭包，不能仅看新增 diff |
| 模型/Prompt | 对应推理结果与模型摘要；直接编译事实无需全部作废 |
| 复现 harness/输入/二进制 | 动态见证匹配和结果 |

使用现有输入清单与增量依赖，不每轮 hash 全仓；命中关键缓存时核对必要内容。缺失依赖就扩大重算范围或标 unknown，不能声称任意工程增量与全量等价。

## 验证

对比相同任务的全历史、日志外置、结构化状态、压缩与经验检索；看任务/义务完成率、陈旧证据使用、重复调查与实际用量。优先扩展既有 tool-use 和 investigation 测试，只有真实长任务才增加独立 ContextManager。
