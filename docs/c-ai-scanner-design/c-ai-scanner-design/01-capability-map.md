# 01 · 能力地图

[返回文档导航](README.md) · [设计架构](02-design-architecture.md) · [预期目标](03-objectives-and-metrics.md)

## 1. 能力结构

```text
C 语言内存与并发 AI 扫描工具
├── F：构建与语义基础
│   ├── 真实构建、链接目标、配置与覆盖缺口
│   ├── 源码事实、对象/区域/代际、语义事件
│   └── 条件化函数摘要、项目契约
├── M：内存缺陷发现
│   ├── 越界、空指针、未初始化使用
│   ├── UAF、double free、失效栈对象访问
│   └── 所有权转移、资源泄漏
├── C：并发缺陷发现
│   ├── 普通数据竞争、真实同步关系
│   ├── 跨线程生命周期与异步回收
│   └── 死锁、原子性破坏、发布与回收协议
├── A：AI 增强
│   ├── 自定义接口语义发现
│   ├── 对象级/协议级主动探索
│   └── 证据缺口规划、复现驱动与报告
├── V：证据与验证
│   ├── 证明义务、候选切片、按需精化
│   ├── 局部路径验证、并发模型检查
│   └── 动态复现、见证检查、证据分级
└── E：工程化与评价
    ├── 根因去重、覆盖与未决披露
    ├── 增量复用、验证调度、预算管理
    └── 真实缺陷/安全反例评测、消融实验
```

## 2. 阶段标识

- **P0：基础与评测底座。** 明确受支持范围，建立真实程序视图及测试集。
- **P1：最小可信闭环。** 对首批内存缺陷与基础线程场景完成发现、验证、报告。
- **P2：语义与召回扩展。** 覆盖自定义资源、异步生命周期及复杂协议。
- **P3：质量约束下的规模化。** 验证增量正确性、复用收益和大仓性能。

表中“首轮阶段”表示开始投入的阶段，不代表该阶段已经完整解决整类问题。

## 3. 基础能力

| 编号 | 能力 | 核心输出与要求 | 首轮阶段 |
| --- | --- | --- | --- |
| F01 | 真实构建识别 | 编译命令、宏、头文件、目标 ABI、链接目标；一个源文件可对应多个编译实例 | P0 |
| F02 | 源码事实与索引 | AST/控制流、符号身份、调用边、源码定位；未解析内容有明确状态 | P0 |
| F03 | 对象与区域模型 | 分配位置、上下文、字段/偏移、大小、初始化区域、实例与生命周期代际 | P0–P1 |
| F04 | 统一事件模型 | 分配/释放/读写/逃逸/发布/同步/任务事件及其路径条件 | P0–P1 |
| F05 | 条件化函数摘要 | 返回值、参数关系、资源责任、共享访问、锁变化及未知副作用 | P1 |
| F06 | 项目契约库 | 分配释放对、引用计数、内存池、取消与注销语义；记录来源和适用范围 | P1–P2 |
| F07 | 语义缺口管理 | 解析失败、未知外部函数、间接调用、汇编、未建模同步原语及其影响范围 | P0 |

关键边界：同一分配点不等于同一实例；同一地址不等于同一代对象；未知函数不能默认为无副作用。

## 4. 内存分析能力

| 编号 | 缺陷或能力 | 正式报告所需的核心证据 | 首轮阶段 |
| --- | --- | --- | --- |
| M01 | 越界读写 | 对象/子对象边界、偏移、访问宽度、目标整数语义与可行路径 | P1 |
| M02 | 空指针解引用 | 空值来源与解引用间的可达传播；输入或调用满足接口契约 | P1 |
| M03 | UAF / 生命周期结束后访问 | 同一代对象、失效事件、后续访问和合法执行顺序 | P1 |
| M04 | Double free | 两次释放针对同一代对象，期间不存在使第二次释放合法的生命周期变化 | P1 |
| M05 | 未初始化使用 | 实际使用的区域未初始化，且该操作在目标 C 语义下确属错误 | P2 |
| M06 | 泄漏与所有权责任 | 在明确责任边界上资源未释放，也不存在合法转移或保留安排 | P2 |
| M07 | 自定义资源生命周期 | 识别内存池、包装分配器、引用计数；支持成功/失败路径语义差异 | P2 |
| M08 | 跨函数与间接调用 | 组合摘要、回调目标与对象别名；候选需要时精化调用上下文 | P1–P2 |

不直接报错的模式：没有判空、函数内部没有 `free`、两个指针来自同一分配点。它们只能触发进一步分析。

## 5. 并发分析能力

| 编号 | 缺陷或能力 | 正式报告所需的核心证据 | 首轮阶段 |
| --- | --- | --- | --- |
| C01 | 执行上下文与共享关系 | 线程/回调/任务入口、对象共享及可能并发关系 | P1 |
| C02 | 普通数据竞争 | 重叠实际区域、至少一个写、同一可行执行中的跨线程访问、缺乏所需 happens-before 关系 | P1 |
| C03 | 同步语义 | 真实锁实例、加锁成功条件、读写模式、线程等待、队列串行化与原子同步 | P1–P2 |
| C04 | 跨线程生命周期 | 获取/借用对象、他线程销毁、随后使用；检查引用持有与等待约束 | P1–P2 |
| C05 | 异步任务与回调回收 | 提交/取消/超时/关闭路径；注销返回后是否还有回调正在使用对象 | P2 |
| C06 | 死锁 | 锁顺序之外，还需可共同到达的持锁/等待关系与可行执行顺序 | P2 |
| C07 | 原子性与顺序协议 | 明确不变量或状态机，以及破坏它的合法操作序列 | P2 |
| C08 | 弱内存与无锁回收 | 目标内存模型、具体原子对象与读取关系、发布和回收协议 | P2 后期 / 按需 |

关键边界：普通竞争剪枝规则不能直接复用于生命周期分析。操作受同一把锁保护，仍可能按“取得指针—销毁对象—使用旧指针”的顺序发生 UAF。

用户态 C、内核、RTOS、中断和 DMA 的同步模型必须分别声明；首版不要求同时支持全部环境。

## 6. AI 与验证能力

| 编号 | 能力 | AI 负责什么 | 结论依据 | 首轮阶段 |
| --- | --- | --- | --- | --- |
| A01 | 语义模型发现 | 阅读实现、调用点、文档与测试，提出条件化接口语义 | 源码推导、已接受契约与适用范围 | P1–P2 |
| A02 | 主动缺陷探索 | 按对象全生命周期和协议寻找传统告警之外的假设 | 与静态候选相同的验证流程 | P2 |
| A03 | 证据缺口规划 | 决定查别名、追回调、精化路径或生成测试 | 工具返回的事实及完整性状态 | P1 |
| A04 | 复现与解释 | 生成驱动、操作序列、故障注入方案和开发者说明 | 合法驱动、可信环境与实际验证结果 | P1 |
| V01 | 证明义务管理 | 辅助解释缺失前提 | 按缺陷类型逐项检查必需证据 | P1 |
| V02 | 语义切片与精化 | 选择下一步需要的上下文 | 数据/控制/别名/并发干扰依赖 | P1 |
| V03 | 局部路径验证 | 提议验证目标 | 忠实程序模型、可具体化反例 | P1 |
| V04 | 并发模型检查 | 识别需专门后端的候选 | 声明的内存模型与合法调度见证 | P2 |
| V05 | 运行时复现 | 生成或修正驱动 | 独立检查驱动、桩函数、插桩和运行环境 | P1–P2 |
| V06 | 分级与排除记录 | 撰写说明 | 正式/条件性/待验证/已排除状态及范围 | P1 |

AI 不凭自身置信度定罪，也不能以多个 Agent 一致赞同替代独立证据。测试支持契约，不等于证明契约在所有路径成立。

## 7. 工程与评测能力

| 编号 | 能力 | 核心要求 | 首轮阶段 |
| --- | --- | --- | --- |
| E01 | 统一候选与根因去重 | 静态与 AI 候选统一处理；保留不同路径和触发条件，避免过度合并 | P1 |
| E02 | 覆盖与未决披露 | 展示解析失败、未解析调用、未建模接口、预算不足和未决候选 | P0–P1 |
| E03 | 摘要与证据复用 | 持久化结构化事实及依赖，而不是仅缓存自然语言总结 | P1 |
| E04 | 增量失效 | 覆盖代码、配置、契约、共享访问、新增依赖及否定性结论 | P3 |
| E05 | 质量约束下调度 | 廉价全局分析铺底，昂贵精化按需；为主动探索保留预算 | P1–P3 |
| E06 | 质量评测 | 真实缺陷、安全反例、修复前后对照、分缺陷类别指标和人工成本 | P0 |
| E07 | AI 贡献拆分 | 比较纯静态、加语义模型、加主动探索、加验证后的净收益 | P2 |

## 8. 能力依赖与投入重点

```text
F01–F04 → F05/F06 → M01–M08、C01–C08
                         ↓
A01 补语义；A02 产生候选；A03 推进验证
                         ↓
              V01–V06 → 正式报告
                         ↓
              E06/E07 → 定位瓶颈
```

优先投入三个核心：**条件化对象生命周期与所有权模型、跨线程对象事件与协议模型、能映射回原程序的错误见证**。工具选型和 Agent 编排围绕它们服务，不反过来决定分析范围。
