# Range 局部修改：查询复用开启／关闭对照

日期：2026-11-11。最新结论：**修正工具参数、事实登记与调查收敛后，同一修改版本的两组均完成裁决、关键事实一致；开启复用的 Token 减少 56.84%，调查耗时减少 29.59%。** 这是单函数调查样本，不是整仓或正式 Range 评测。

## 最新实现及测量范围

沿用 `_lifecycle_format_topic` 的局部格式分隔符修改，仍只复制两个编译单元及其实际项目头文件，真实 native 提取与 `deepseek-v4-flash` 调用不替换。预算保持每组最多 8 轮、单请求最多 8,192 Token、超时 120 秒、不重试。开关两组使用相同当前请求和 BuildContext，各自从同一建档缓存复制；原始 Range fixture 和 ground truth 未修改、未作为模型答案输入。

针对已观测问题，本轮完成以下修正：

- **参数边界。** 搜索契约说明文本／文件只支持字面子串匹配，空 `kinds` 表示无过滤；非空过滤和不适用的模式仍拒绝。模型传来的字符串 `"null"` 仅在已指定文件的空 symbol ID 或首屏空 view ID 中恢复为空，不改搜索内容、文件名、有效 ID 或后续分页。
- **当前事实登记。** 普通 V3 的最终引用必须来自当前 FACT_V3 或输入目录；直接使用 TOOLFACT 会获得登记指引，历史响应提取也不能绕过。没有 counterexample 事实类型时，不向模型暴露只服务于反驳事实的可选字段。
- **调查收敛。** 按候选条件读取、及时登记，再决定是否补查；允许的事实类型不作为必填清单。缺失请求采用显式 null／object 分支，完成裁决与补事实请求的互斥要求不变。没有自动把错误输出改成 verified，也没有恢复历史 Proof。
- **明确实验入口。** 原探针实际选定了函数入口，却没有把入口写入请求，造成对外部调用者的分歧。现在从真实 entry plan 写入该函数的分析根和自路径，只核查函数入口到候选操作的路径；不主张已证明整个应用的外部可达性。该修正两组完全相同，因此新旧实验不作纯缓存因果对照。

### 测试范围与变更

选取当前 Range 的 [`_lifecycle_format_topic`](../../test/range/src/lifecycle.c)（326—336 行），在独立实验目录中复制 `lifecycle.c`、`utils.c` 及其实际包含的项目头文件。仅修改格式分隔符：

```diff
-    snprintf(topic, sizeof(topic), "%s-%u", prefix, id);
+    snprintf(topic, sizeof(topic), "%s:%u", prefix, id);
```

原有 `topic[sizeof(topic)]` 写入、函数位置和行号保持不变。仓库中的 Range fixture 及用户已有修改未改动；没有复制或读取 ground truth，也没有运行这些 C 函数。

在 WSL Ubuntu 下使用真实 clang-18／native 提取和 `deepseek-v4-flash`，针对同一个显式给定的数组边界候选执行 V3 调查。工具包括当前源码读取、代码搜索和关系查询，模型响应未替换。每组最多 8 轮，单次请求上限 8,192 Token、超时 120 秒、不重试。

顺序为原始版本建档 → 修改后开启复用 → 修改后关闭复用。两组当前版本的候选请求逐项相同，BuildContext 相同，模型、Prompt 和工具配置相同；两组缓存分别复制自同一建档结果，仅查询复用开关不同。原始版本与当前版本的 BuildContext 不同。

这是 **Range 单函数调查实验**，不包含项目级候选发现、initial、最终 Finding 授权及报告流程，不是 trial/formal 或 Range 全量 recall／precision 评测。当前原始工具证据不能代替程序 Proof。

### 结果解释

1. **复用机制生效。** 原始调查虽未完成，成功读取仍形成计划。修改后命中计划，重新执行源码读取和文本搜索；实际返回内容包含新的 `%s:%u`，没有用旧源码替代当前数据。两次“变化”按完整工具返回值比较，不解释为两项程序语义变化。
2. **调查路径出现分叉。** 开启组还读取了头文件中的公开声明，最终模型认为入口可达；关闭组识别到同一数组越界写，但仍要求补充 `source_sink_reachability`。更多调查、上下文和模型轮次抵消了提前查询的收益。此解释来自保存的轨迹，单轮不能隔离模型随机性的影响。
3. **命中不等于省调用。** 两组均有 2 次无效搜索参数请求，开启组仍用满 8 轮。预先给出查询结果没有使模型稳定收敛到更短的调查。
4. **不能将 `verified` 计为最终 Finding。** 两组结构化响应均通过解析，引用均属于各自当前会话，但都没有登记 FACT_V3。本实验未执行最终 Finding 授权，也未证明两组证据闭合程度相同或增量零漏报。

本轮没有为获得有利结果反复重跑或修改产品。准备阶段曾因复制了未包含在编译数据库中的其他 Range 文件而失败，模型调用为 0；收窄到两个编译单元及其实际头文件后完成了上述唯一一次三阶段模型实验。

### 对方案的影响

这项结果补充了此前小型 C 样本的局部 Token 下降，说明当前首版只能确认“跨构建步骤复用可用”，尚不能承诺稳定的整轮成本收益。后续应优先处理实际暴露的工具参数错误、当前事实登记和可达性义务的收敛，再评价剩余义务复用；仅扩大计划命中率不足以证明商业降本效果。
