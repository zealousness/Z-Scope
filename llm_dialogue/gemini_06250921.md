### 该 JSON Schema 核心结构概述

大模型（LLM）在完成语义建模后，其输出的 JSON 响应必须严格符合该 Schema 定义的 `function_snapshot`（函数语义快照）格式。主要包含以下字段（均为 `required` 必填项）：

1. **`func_name` / `location` / `summary` / `role`**：
   * 函数名、代码物理位置、以及用中文书写的函数功能摘要与 API 契约角色。
2. **`inputs` (输入参数)**：
   * 每个输入参数的名称、含义、信任级别（如 `trusted` / `untrusted`）和可空性 (`nullable`)。
3. **`outputs` (输出结果)**：
   * 返回值的名称、成功/失败时的取值范围以及调用者的清理义务 (`caller_obligation`)。
4. **`memory` (内存生命周期事件)**：
   * 记录内存的申请（`allocations`）、释放（`releases`）、所有权转移（`ownership_transfers`）、别名关系和缓冲区边界限制。
5. **`resources` (句柄及资源状态)**：
   * 跟踪文件描述符、Socket、Mmap 等句柄资源在不同函数退出路径（Exit Paths）上的最终状态（如 `released` / `leaked`）。
6. **`error_paths` (错误处理路径)**：
   * 描述所有的异常返回路径、执行的清理动作（Cleanup）以及状态一致性。
7. **`concurrency` (并发与同步)**：
   * 全局/共享状态的读写、互斥锁的加锁/解锁事件（`locks`）、调用路径上的持锁顺序（`lock_order_by_path`）、线程创建副作用以及引用计数或原子操作。
8. **`callees` (子函数调用契约)**：
   * 本函数所调用的主要子函数列表，及其对应的安全风险。
9. **`suspicious_points` (可疑隐患点)**：
   * **这是推动后续漏洞扫描的核心字段**。Modeler Agent 会指出该函数内部可能违背 9 大安全 Skill 的隐患（如 `resource_lifecycle` 资源泄露、`stack_escape` 栈地址逃逸等），为后面的 `deep_worker` 指明工单切入点。

$defs是什么？

在 JSON Schema 规范中，**`$defs`**（在旧版本规范中称为 `definitions`）是用于**定义可复用的子 Schema** 的标准声明区。

它的主要作用是**减少代码冗余并保证规范的一致性**。

#### 如何引用？
只要在主架构中，有任何字段需要采用这个“事件列表（数组）”的格式，就使用 `"$ref"` 关键字指向这个锚点（通过 JSON Pointer 路径 `#/$defs/events`）：

例如在该文件的多个地方被复用：
* 内存分配：`"allocations": {"$ref": "#/$defs/events"}`
* 内存释放：`"releases": {"$ref": "#/$defs/events"}`
* 锁事件：`"locks": {"$ref": "#/$defs/events"}`
* 线程副作用：`"thread_effects": {"$ref": "#/$defs/events"}`

这样大模型（LLM）在理解 Schema 时，这些具有相似“事件轨迹”特性的数据字段，就会统一被校验为包含 `line`、`kind`、`resource` 等标准结构的事件对象。
