## 1. 总体决策

保留静态事实先行、语义推理受约束、统一候选与验证的产品定位。优先弥补三个缺口：

**发现前可以主动取证；昂贵分析围绕具体待证事项调度；高价值候选可以进入独立执行和复现。**

不以“增加更多 Agent／后端／规则”为成功指标。增加的能力必须能证明带来独占真问题、减少证据缺失、降低重复成本或改善覆盖边界。

## 3. 目标逻辑结构

```text
目标项目／构建变体／代码版本
    │
    ├─ 轻量目录、文本与符号检索
    ├─ Clang TU／AST／CFG／宏／类型事实
    ├─ 已验证接口契约与固定 Wiki revision
    └─ 按需 SVF／局部路径事实
             │
             ▼
    程序入口 + 安全事件 + 未知／冲突 + diff／历史模式
             │
             ▼
    审计单元与覆盖账目
       ├─ 原有确定性／backend 候选
       ├─ 原有一次式 candidate-blind 发现
       ├─ 有界 Research Worker（新增，先 shadow）
       └─ 条件性建模观察（新增，独立来源，先 shadow）
             │
             ▼
    既有 CandidateRegistrar → Ledger freeze
             │
             ▼
    既有 V0～V3 + 可选独立验证执行器
             │
             ├─ 新关联问题 → 既有 append Ledger
             └─ 统一 outcome → 报告／复核／SARIF
```

这是逻辑职责划分，不要求每个框都实现成一个新服务或数据库。优先扩展当前类、store、scheduler 和报告元数据。

## 4. 五条技术主线

### 4.1 代码索引：覆盖正确性优先于表面吞吐

当前每个源文件选取首个编译命令；不能把该结果写成所有产品变体都已覆盖。P01 先做编译上下文清单，保留未选变体及原因，不立即全量展开组合。源码、编译命令、依赖、工具版本、链接目标与资源模型共同决定事实是否可复用。[R08]

增量验收要比较相同目标版本下的“增量结果”和“干净重建结果”，不能只判断缓存命中或更新成功。先比较确定性事实，规范化时间戳／运行 ID，但不能忽略符号身份、类型、宏分支、边界截断或删除传播等语义字段。

性能测量分开报告：首次可查询、基础事实、类型引用、bitcode 编译、链接、WPA/Saber、语义建模、LLM 发现、验证、序列化。只有知道瓶颈在哪里，才决定是否推进 R01 的增量 SVF 实验。

不承诺任意变更下的全程序零漏报。对固定支持范围的确定性增量验收要求语义等价；范围无法证明时扩大受影响范围或明确 partial／不可复用。对于 LLM，缓存复用与新模型调用的随机结果要分开比较，不能要求独立随机采样逐条一致。

### 4.2 扫描入口：由函数根转为可回答的命题

继续使用现有入口作为可达范围，不增加一堆硬编码业务接口名称。D03 细化四类单元：输入－敏感操作、资源生命周期、共享状态／回调、协议契约。

覆盖单位从粗粒度家族＋文件，逐步细化为“缺陷家族＋对象／位点＋构建上下文＋路径边界”。同一文件已有一个候选，不应把其他对象判为已审计；没有调用者也不能单独证明回调不可达。

入口数／函数数上限造成的未调度区域要有显式状态。程序负责排序与预算；模型只拿任务必要事实，不接收当前候选存在性、历史 verdict 或 benchmark 答案。

### 4.3 项目知识：条件契约＋资格验证

保留 Wiki 与 user_config 已有边界。文档契约回答“应当如何”，编译事实回答“实际如何”，调用／运行证据回答“在什么条件下发生”。三者不能互相冒充。

K02 首先覆盖一种协议：成功转移所有权、失败保留所有权。契约应能表达返回值条件、参数／对象身份、资源域、锁前提与失败后状态。LLM 提议先是 advisory；只有实现或受限检查器符合资格时，才允许用于解除对应义务。

文档－实现冲突应产生待证事项，而不是让文档覆盖源码。无函数体的外部接口要保留不确定性，不能靠 alloc/free/register 等名称授权所有权效果。

P02 再试验“确定性关键契约前置，其他语义按需补建”。调度必须包含未知敏感接口和覆盖缺口，不能只依赖已有候选，否则未知语义导致的候选缺失会永远被跳过。先 shadow 记录拟节省任务与潜在漏检，再考虑实际跳过。

### 4.4 后端发现：双路径，而非全面重型 Agent 化

保留原来一次式发现作为低成本通道。仅对可明确指出关键缺失事实、且有可执行查询计划的单元升级 Research Worker。

Worker 可用：搜索、源码读取、candidate-blind 语义投影、代码图、数据流。禁止静态候选查询、报告读取、扫描启动、任意 shell／网络。新增证据必须由程序登记，不允许模型给任意文本自造 evidence_ref。

当前主动发现校验只允许原投影证据与原单元函数。因此先做 D01：将新工具证据绑定到不可变修订、受控范围及调用轨迹，再做 D02。跨单元查询通过有界扩展／子单元清单授权；不能为了通过 schema 去掉来源检查。[R06]

K01 对建模怀疑点使用独立 shadow 来源。最低门槛是具体对象或 source/sink、真实位置、违反性质、成立条件、缺失事实；模糊“可能有风险”不登记。shadow 观测复用现有机制，不能修改主 Ledger 冻结规则。

### 4.5 证据后续：从复核文字走向独立复跑

V01 先做一个小模块的 ASAN 验证闭环：候选 → 验证计划 → harness／输入 → 独立 runner → 原始日志与构建身份 → 证据适配。结果必须明确是受控 witness、未复现、执行失败或不适用，而非只输出 true/false。

V02 再扩展 TSAN／CBMC。TSAN 无告警不等于无竞争；CBMC 的有效结论绑定模型、外部函数假设和展开边界；ASAN witness 不自动等于可利用性证明。

不更改现有 disposition 枚举。新增执行结果是 provider 元数据，经原有资格检查后才影响结论。不能把外部工具的“confirmed”原样升级成内部程序 proof。

## 5. 工具契约差量

### 5.1 `search_code`：扩展检索域，保持六工具词汇

提议新增可选 `scope: symbols | text | files`，省略仍为当前符号搜索。

- `symbols`：保持旧参数、排序、symbol_id、分页和输出行为。
- `text`：MVP 只支持字面量子串，不加入任意 PCRE；匹配返回真实项目相对路径、行号、片段与版本信息。
- `files`：MVP 对受许可相对文件路径作字面量子串匹配；无需立即支持任意 glob／regex。

`text/files` 不应触发符号目录或 AST 初始化。`read_code` 现有路径读取复用相同读取许可；匹配不是调用边、别名或路径证明。

建议先使用有界标准库实现或仓库现有依赖；rg 仅作为可选可探测加速器，缺失时不改变语义。目录遍历、全文读取、命中数量和返回体分别有边界；遇到边界保留 partial，不伪造已扫描全部文件。精确定义快照内分页顺序，不能边翻页边漏项／重复。

MVP 可采用有界结果页缓存：查询 identity 绑定代码视图，分页在该视图上继续；未扫描完的 corpus 必须单独显示，翻完当前结果页不代表全仓搜索完毕。

### 5.2 `get_semantic_context`：增加严格只读语义

提议新增 `refresh_policy: cache_only | ensure_current`。普通现有调用省略参数保持原行为；只读会话强制 cache_only。显式要求刷新却不具备权限时必须拒绝，不静默执行。

cache_only 不调用 resolver、不发模型请求、不写 snapshot／工作簿／KnowledgeDB、不触发建模或后端预热。仅使用已有可验证版本元数据；无法核对完整性返回 unknown／unavailable，不通过可能隐藏建模的 helper 来“检查一下”。可有普通审计日志，但不得写项目语义状态。

MCP annotations 按工具注册确定，不是逐次参数切换。混合支持 ensure_current 的注册仍须保守 non-readonly；只有服务端强制所有请求 cache_only 的只读 profile 才能声明 readOnlyHint=true。不能只改标签而不改实现。[R05]

候选盲 worker 的语义结果采用专门投影，去掉 suspicious_points、findings、旧 verdict、review memory 等结论性背景。不要误删正常源码文本中的 candidate/rule 等词汇。

## 6. 外部 Coding Agent 的定位

### A. 外层 Agent 调 Z-Scope MCP：先完成

外层 Agent 自带文件／Git 检索，Z-Scope 提供精确程序事实。T03 提供项目锁定、只读工具 allowlist、无模型刷新及无扫描启动的配置示例与 smoke。没有必要为每次 grep 再启动一个 Agent。

### B. Z-Scope 调外部 Agent：可选执行器

A01 只为明确任务包启动一个受限 worker。先提供 fake adapter 与离线 artifact 导入，再选择一个实际供应商做 smoke；不要求同时支持 Claude、Codex 及多个 SDK。

防止递归扫描，限制网络和可写目录，不自动继承全部宿主环境。SDK 的子 agent 文本不能直接成为证据。外部 worker 的模型 token 无法精确取得时明确 unknown，不用字符数伪造供应商 usage。

### C. Codex Security：独立对照，而非首批硬依赖

本次已核对其官方仓库 SDK README：有 TypeScript／CLI、扫描与验证、JSON／SARIF 等输出；1.0 前 minor 版本可能改变 API，部分请求存在额外访问要求。[E03]

A02 固定实际可用版本，先在授权小型 fixture 上做独立扫描及结果导入。认证、访问资格、网络与许可没通过时保持 deferred；不得以安装 npm 包为前提阻塞原生 Z-Scope 改进。不能直接假设用户订阅包含相应能力。

## 8. 验收与回滚

硬门槛：旧协议兼容、证据来源有效、只读无副作用、truth 隔离、冻结不可变、未决不消失、取消不泄漏、源码版本变化拒绝旧证据。详见 [ACCEPTANCE.md](ACCEPTANCE.md)。

性能目标不预设加速倍数。先记录重复试验的分布及覆盖范围，在同硬件、同数据、同后端、同模型和等价结果下比较。试验阶段可以更慢但带来独占真问题；应明确属于能力增益而非性能优化。

默认行为变化必须有单独的推广证据；本交接不授权更改 rollout 晋级门槛、降低 proof 资格或打开全局无限调查。回滚以关闭新增实验路径、保留可读旧缓存和恢复旧协议行为为主，不删除用户扫描资产。
