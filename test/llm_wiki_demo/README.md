# LLM Wiki context demo

这是一个专门验证项目文档约束如何影响 Validator 判断的小型 C 项目，
不是正式发布 benchmark，也不包含评分答案。`include/wiki_demo_api.h` 中的
五个函数是项目对外公开的入口，`src/` 只保存实现。

## 项目和模块约束

### 标签 API

所有对 `wiki_copy_label` 的有效调用都必须经过项目外部的唯一 API 网关。网关在
调用前强制验证 `label` 非空、采用 UTF-8 编码，并且字节长度为 1--31；不满足
条件的请求不会调用该函数。该约束是调用方前置条件，源文件不重复执行长度检查。

### 命令 API

`wiki_execute_command` 的参数来自调用方。项目没有声明一个统一的安全命令白名单，
调用者必须在更高层完成授权和命令策略检查。该说明不构成当前函数的安全证明。

### Frame API

调用 `wiki_decode_frame` 时，调用者必须保证 `frame_len <= out_len`；函数返回复制的
字节数，空指针输入无效。缓冲区大小关系仍需要结合当前调用路径的代码证据核对。

### 端口 API

`wiki_parse_port` 接受十进制文本，允许范围为 `1024..65535`（含边界）；其他值应
被拒绝。

### 回调注册 API

`wiki_register_callback` 的注册表由同一个互斥锁保护。注册操作完成后才能把回调交给
其他线程执行；回调执行期间不得重新进入注册表。

## Validator 使用说明

这些文字是项目、模块和公开 API 的语义约束。它们可以帮助 Validator 判断调用方
前置条件、可达性和不确定性，但不能替代 CodeIndex、调用图、运行时证据或
deterministic proof。文档与代码冲突时，以代码事实为准；只有缺少决定性事实时才
保留为待复核。
