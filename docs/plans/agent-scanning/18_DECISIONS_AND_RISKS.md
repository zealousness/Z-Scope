# 18 · 决策、取舍与剩余问题

## 用户已确认

| 决策 | 结论 |
|---|---|
| 产品主线 | 专业扫描优先，通用 Coding 后置 |
| 目标顺序 | 低误报、高召回、性能、项目理解、易用体验 |
| 自动复现 | 默认允许独立目录生成/编译/运行测试，不修改业务源码 |
| 平台顺序 | Linux 与嵌入式/RTOS 都重要，先 Linux 闭环 |
| 重点 | 内存/资源，包含特殊业务协议与生命周期 |
| 交互 | 非工作时间自主运行，集中启动和验收 |
| 兼容性 | 不考虑旧接口兼容，可以替换冗余工具/步骤 |
| 安全专题 | 删除原 09 与配套审批/沙箱平台建设要求 |
| 网页能力 | 产品后续不增加 web 访问；保留本地 WebUI/模型连接 |
| 开发方式 | JUST YOLO，小切片与真实相关验证，不搞代码冻结/重门禁 |

## 技术默认决策

| 决策 | 理由与修改条件 |
|---|---|
| 复用扫描四平面和统一裁决 | 已有大量实现；改具体流程不另造结论真源 |
| 对象/代际/责任为扫描主线 | 满足内存资源重点，并抑制别名/生命周期误报 |
| BuildContext 贯穿事实与契约 | 已发现多变体存储缺口，属于正确性前提 |
| 静态摘要+实际需求建模 | 替换全可达前置 LLM；覆盖/召回对照验证后清理旧路径 |
| 证据增量驱动验证 | 删除重复读同一材料的多轮复判，保留未决原因 |
| 静态/动态见证均可确认 | 不让必须动态复现成为召回瓶颈，不让模型自述成为证书 |
| 复用 ASan/TSan，新增生成器 | 执行器已有且历史验收完成，实际缺口在自动计划 |
| 一个配置入口，提议 v3 | 无兼容目标，可简化路径与预设；UI/CLI 同源 |
| 单本地 job owner + 小状态库 | 满足夜间续跑，不建立分布式 Agent 平台 |
| 项目契约/Wiki/反馈分域 | 项目理解有来源，模型猜测不污染证明或抑制 |
| 当前保留 Clang/SVF/Saber | 真实可用资产；若新方案有独占收益并可替代则删对应冗余 |
| 求解器/新扫描器按需 PoC | 先 CBMC 局部缺口，其余按样例，不全量堆叠 |
| 原 Ledger freeze 可替换为批次 | 需要追加发现而不无限递归；不是开发代码冻结 |
| managed rollout 不做新预设长期依赖 | 默认行为简单明确；协议清理与消费者一起修改 |

上述是可据此开发的默认方案，不把目录名、阶段数量和候选后端设为不可变约束。

## 风险与具体措施

| 风险 | 信号 | 措施 |
|---|---|---|
| 低误报靠少报 | precision 上升而未决/FN 激增 | 联合报告最终 recall、候选 recall、误排除和 backlog |
| 多配置混淆 | 同文件不同宏/ABI 得到互相污染的事实 | 编译实例进入全部消费者，局部目标先闭环 |
| 名称/抽象身份冒充对象 | 错池、不同实例、复用地址被合并 | 对象域/代际/unknown 与安全反例 |
| 共同锁掩盖 UAF | race 被排除后生命周期候选消失 | 分开性质与剪枝 |
| 需求调度漏难例 | 只选当前候选关联接口 | 对象/协议盲覆盖、延后原因、全量对照 |
| 复现制造缺陷 | stub 改释放/锁、非法初始化 | 检查原程序映射和接口前提 |
| 非确定性 witness 长期未决 | 一次真实触发却因混合重放一直不确认 | 先保留分布，独立比较确认策略，质量优先 |
| 恢复用错旧证据 | 源码/构建已变仍复用结果 | 按依赖失效，动态 receipt 不从 JSON 恢复 |
| 项目模型互相污染 | 文档/人工/模型来源混合 | 分来源、条件、revision 和冲突 |
| 用户又要填很多参数 | 多份 YAML/profile/工作簿 | 一个配置入口、自动画像、高级折叠 |
| 原重流程复活 | 每个小包等冻结/签发/全矩阵 | 相关正反例和运行记录即可，正式发布另论 |
| SDK/后端堆叠 | 多个通路重复消费相同事实 | 按独占质量收益和成本 adopt/drop |

## 后续需要真实项目信息的选择

首个业务工程/平台、典型资源 API、真实构建和测试入口、模型/机器容量、夜间时窗以及质量目标绝对值，应在开发样例准备/首次部署时确定。它们不阻塞本计划完成，也不应提前猜成已知用户项目事实。

需要改变产品目标、默认修改业务源码、支持范围或引入新的外部服务时再询问用户。常规实现细节、复用现有库、删重复步骤与相关测试不设额外确认。

## 决策更新方式

只记问题、采用方案、可替代选项、证据与影响；必要时改本包和相应模块说明。不要建立与任务状态并行的多套审批/验收台账。
