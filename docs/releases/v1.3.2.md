# Z-SCOPE v1.3.2

v1.3.2 是在 v1.3.1 C/C++ 稳定线之上的演进取向版本。包内 `zscope._version.__version__` 为版本唯一真源，Git tag 必须为 `v1.3.2`。`zscope.candidate.v3.3`、`zscope.decision-context.v3.3` 等是内部 schema 版本。

## LLM Wiki 项目知识层

- 新增 `zscope/wiki` 子系统：从 `project.root` 递归发现 Markdown，确定性区分说明性文档、生成物、运行时指令、benchmark truth、敏感内容和未知文件；只有 explanatory 文档进入 source index 与 Wiki 编译输入，原始文档只读。
- 扫描 workflow 在入口发现后执行一次 session 级 `wiki_compile`，等待编译、发布或 direct-source fallback 全部结束再启动入口分析；批量入口、辅助 Analyzer 与 scan-level Validator 共享同一个只读 `ProjectKnowledgeService`，session 在扫描结束时统一关闭。
- `WikiStore.apply_changeset()` 在 staging、SQLite projection 和原子 active pointer 之间发布不可变 revision；`audit-events.jsonl` 是 `log.md` 与 active transition replay 的唯一事件来源，`log.md` 可从完整事件链原子重建。
- Compiler 终态工具 `emit_project_constraints` 只接受最小语义 proposal；程序生成稳定 constraint ID、scope、authority、status、revision/digest，并校验来源、去重和 stale 传播。
- source index 独立于 Wiki store：Compiler 不可用或 Wiki 损坏时仍可返回带路径、标题、行号和 digest 的原文摘录。
- `project.wiki.mode` 默认 `off`；启用后状态目录由 `project.wiki.state_dir` 决定（默认 `.zscope_knowledge/wiki`）。新增 `zscope-wiki` CLI 与 Web 只读 `/api/wiki/*` 端点；Windows 上 WikiWriterLock 使用非破坏性 pid 探测。

## 自适应语义发现与 Validator v3

- balanced/deep 额外构建 Security Semantic Map，coverage-gap planner 在 candidate-blind 约束下主动提出 hypothesis；确定性/backend 候选走低成本快车道，所有来源统一进入全局 Candidate Ledger。
- 验证分层收敛：V0 确定性 proof、V1 无工具严格 schema 单次判定、V2 按安全义务一次补齐事实后单次复判、高风险 V3 有界调查。每个 validation cluster 只有一个最长 50 次模型迭代的连续会话，只能使用只读白名单工具，可引用事实完全闭合后才进入默认视图。
- 验证结论保留完整 reasoning 过程，并新增 `user_rebuttal` 人工复议字段；v3 direct completion 应用配置的 max_tokens 并强制 gateway-safe `tool_choice`，JSON 修复调用同样收敛。
- 工具循环守卫与上下文压缩修复降低长会话漂移；Skill 与 Agent 契约默认不再截断。

## Clang 索引与 SVF 值流性能

- 新增源码构建的 `zscope-clang-indexer` 批量前端（portable 包内随 LLVM 18 安装于 `tools/llvm18/`），`indexing.clang.frontend: auto|batch|lsp` 控制批量抽取与 clangd 回退；严格 `batch` 下禁止 LSP 降级。
- clangd 基础抽取支持可选多实例分片池；include-closure 作用域的部分派生重建、按 use-site 身份解析派生引用、避免急切声明身份扫描显著降低大型项目重复索引成本。
- clangd 异常退出记录退出码与传输诊断；index-wait 超时软化并加固 progress token 生命周期。
- SVF 支持可选懒 scope-first bitcode 构建、heap 预算内并行 Saber 分组执行，并跳过无法放进配置堆预算的 wpa 组；相关机制文档见 `docs/modules/retrieval-backends.md`。

## Linux Portable 四包发布

- 按架构（x86_64/aarch64）× 语言（cpp/java）交付四个解压即用的 `zscope-{version}-linux-{arch}-{profile}-portable.tar.gz`；构建基线锁定 Ubuntu 23.10/glibc 2.38，运行时使用宿主 glibc。
- 每包附带 ABI JSON/Markdown、SPDX SBOM、smoke 证据与签名校验和；验收在 `--network=none` 容器中执行，覆盖普通用户、只读包、含空格路径与断网环境。
- C/C++ 包内置 clangd 22.1.7 与独立 LLVM 18/gllvm/SVF 3.2 bitcode 链路；Java 包内置 JDK 21、Maven、预编译分析 JAR 与 Joern Java 功能。
- 旧 `install.sh` 分体资产与 `releases/{version}` 回滚布局仅保留兼容，不用于安装 portable 包；完整路线见 `AGENTS.md` 的 Linux Portable 发布路线。

## 规则治理与 public config v2

- `zscope.yaml` 收敛为 LLM、项目范围、入口发现、审计重点、scan depth、后端拓扑、SVF 规划、并发和规则扩展；Agent 拓扑、预算、缓存、报告与稳定算法默认值由打包的 RuntimeSpec 提供。
- `rules.disabled_ids` 统一覆盖 Java local、C/C++ Regex、Clang CFG/matcher、Graph、YAML pack 和 Python provider，优先于 `enabled_ids`；不抑制 SVF/Saber、Joern/Java provider backend signal，也不阻止 LLM 独立发现。
- 旧 v1 配置必须显式迁移（`zscope-config migrate`），未知字段严格失败。

## 可观测性与运维

- conversation-event v2 录制流逐事件记录 llm_client 行为，`--verbose` 写入 `.zscope_conversations/`；LLM provider 4xx 拒绝输出 wire-shape 诊断。
- 批量报告携带 task id，扫描状态使用终端标记并按目录定位任务日志。
- SQLite 运行库下限明确为 3.8.10.2。
- Python 基线切换到 3.13：`requires-python >= 3.13`，mypy/Black 目标同步 3.13；移除 Python 3.9–3.14 兼容矩阵、多版本带哈希约束与 CI workflow，规则 provider 的 3.9 `importlib.metadata` 回退一并清理。质量检查（pytest、compileall、mypy/Black 基线、benchmark hygiene、secret scan、依赖/许可证审计）转为本地命令执行，命令见 `README.md` 开发命令与 `requirements/README.md`；测试一律在 Linux 环境执行，Windows 上在 WSL Linux 用户态中运行，不用原生 Windows 解释器形成测试结论。
- Java Preview 修复项目规则缓存初始化、限定名批量入口身份与 WSL preflight；首个五轮 Java Preview LLM 聚合（`c047dca`）归属 v1.4.0 Preview 基线，不参与 v1.3.2 C/C++ 发布门禁。

## Benchmark 与门禁

v1.3.2 继承 v1.3.1 的冻结 C/C++ 基线（`docs/range_reports/v1.3.1-cpp-baseline.json`）。正式 v1.3.2 结论必须在受保护的 `v1.3.2` 发布 SHA 上按 Range 协议重新执行并绑定，不得复用不同 SHA 的历史结果；本说明不预先声明任何未运行的正式指标。正式发布 workflow 验证相同源码 SHA 的 Formal Benchmark 与受保护 Balanced Default Attestation 后创建 draft Release。
